# Standing Watch

A watch is a loop whose state outlives the context that wrote it. Every pass wakes with less than the last one had, acts on what it can read, and hands the next pass whatever it wrote down. That is the whole difficulty. A note written when it was true is read as fact when it is not. The loop's own reasoning is the thing most likely to go stale unnoticed. Everything here follows from that.

## The two artifacts

A watch runs on exactly two written surfaces, and they differ in what they hold, not in how they are formatted.

- **The runbook** is the procedure: what a pass checks, in what order, with which commands, and what each result means. It is project-specific, committed, and changes only when the procedure changes.
- **The ledger** is the state: what is true of the watched system right now and what the loop has learned about it. It is gitignored, lives under `.kit/`, and is rewritten in place rather than appended to.

Nothing the loop needs lives only in a session's context. Anything else a tick produces (a ping, a commit, an intervention on the watched system) is an output of that tick rather than a loop artifact. Those two artifacts are the loop's entire memory, and the class is closed.

The order a pass ends on is fixed by the tick order below, at step 4. A pass that ends by arming before it writes loses the pass when the write does not happen. A watch arms for two different reasons, and the class is closed at two. The safety arm is the standing heartbeat, a repeating timer whose only job is to guarantee that some wake exists. The paced arm is a one-shot that sets when the next pass runs, and it is what the end of a completed pass decides. The tick order opens with the first and closes with the second, and states when each is armed. Both steps read as ensure rather than add.

## The ledger's shape

Two kinds of content, in separate sections, never interleaved:

- **Standing**: prohibitions, mechanisms confirmed in the system's source, and do-not-reopen traps. What stays true without re-measurement.
- **Situational**: the board as of the last pass, open interventions, recent pings, the length of the quiet streak. Everything a later pass must re-derive before acting on.

Both kinds answer one admission test before they are placed at all: a line belongs on the ledger only if a successor with no context needs it to resume the watch. The test is not whether it is true, not whether it was hard-won, and not whether it can be dressed with an evidence time and a re-derive command. A withdrawn reading, a correction, and the story of how an instrument was found broken can each carry both and serve no resumption. Two tells mark a line that fails the test: it argues rather than states, or its subject is the keeper's own reasoning rather than the watched system. What such a line carries, where durable, goes where the destination rule at the end of this file sends it, and otherwise it is dropped. The ledger is not its second home.

**Doubt falls to the cheap side, at both forks.** A line meets two forks on its way onto the ledger. The first is whether it belongs at all, which the admission test above decides. The second is which of the two kinds an admitted line is, which the two-kinds rule that opens this section requires. Doubt at either fork falls the way whose error is the cheaper one. At admission, a line the keeper cannot confidently say a successor needs stays off. That default is the admission test's tie-break for doubt, not a stage every line passes through. The test decides every line, and the default answers only where the keeper cannot call the test's answer. Kept off wrongly, a line costs one of three things. A line the watched system reproduces costs a re-derivation on each pass that needs it, under the tick order's re-derive step. A durable line with a home under the destination rule at the end of this file costs one read of that surface. A line that is neither costs the line itself, and that loss is accepted rather than argued away. The content the test above and this default exist to keep off, a keeper's own reasoning and an episode's narrative, is by its nature recorded nowhere else. A default that spared the irreplaceable would spare the whole of it. Kept on wrongly, a line survives every rewrite this file performs, since none asks again whether a line belongs. Supersede, under its own rule below, fires only on a changed fact. The prune, under its own rule below, moves only what supersede has retired. The per-pass write under the tick order writes back what the re-derive step produced, and supersede is its rule for what changes on a line. A line the re-derivation refreshes is rewritten current. A line it neither confirms nor contradicts is one no fact changed under. Supersede does not fire on it and nothing else in this file removes it, so it is left standing as found. What the default keeps off leaves by the same route as a line that fails the test.

**The admission default is residual.** It decides only what no rule has already placed. A class is placed when a rule of this file or of a consuming skill names it as ledger content (a rule places a class, where a keeper writes a line). That naming is the rule's judgment that a successor needs the class to resume the watch. The two-kinds rule that opens this section places its members. The read protocol below is placed by its own rule. The destination rule at the end of this file places the pass record. Those are this file's own placing rules, and a consuming skill's rules place what they name in the same way. Placement is not an exemption from the admission test, which exempts nothing, this file's own kinds included. What a rule's naming settles is that a successor needs the class. That is the one question on which a line the keeper recognises as a member is spared the default's doubt, save on the two members named below, whose lines this file's own rules answer too. The test keeps its refusal whole. It refuses a line that is not the member it presents as, since a withdrawn reading, a correction and the story of a broken instrument can each be dressed as one and are not. It refuses a member whose particular line no successor needs to resume the watch, the class being needed and that line of it not. That second refusal is asked of the line rather than of the class, so the keeper can be in doubt on it. That doubt is the admission default's like any other, save on those same two members. A recognised member outside those two, whose particular line the keeper cannot confidently say a successor needs, stays off, under the default exactly as the paragraph above states it. It leaves by the route the admission test's paragraph states: the destination rule where it carries something durable, and otherwise dropped. The default therefore lives in the test's doubt branch and nowhere else. Its domain is every line the keeper cannot call the test's answer on and no line it can, the test answering those. That doubt takes three shapes: a line outside every named class whose need the keeper cannot call, one the keeper cannot recognise as a member, and a recognised member whose particular line it cannot say a successor needs. The third shape does not reach two of the standing kind's members, because a rule of this file already answers the line's need and leaves the keeper nothing to call. A prohibition is needed exactly while it binds, and whether it binds is never the keeper's question. Where it cites a condition, the re-measure step in the tick order measures that condition every pass. A condition reading false means the line does not bind this pass and never that the line has been retired. Where it cites none, it binds until the operator's word retires it. The kind fork below states the same when it says such a line is obeyed stale until the operator's word retires it. A do-not-reopen trap is needed however old it is, by the prune rule. A recognised prohibition or trap therefore takes the standing list and leaves it only when its source retires it. That retirement is the changed fact supersede fires on for these two members, and the only one. What the test still refuses of either is the first refusal's case, a line that is not the member it presents as. That line takes the default's route above. On the standing kind the third shape reaches the mechanism confirmed in the system's source, whose loss is priced above as a re-derivation. What earns those two members their exemption is the property rather than their names: no probe of the watched system reproduces them, and their loss licenses the act they exist to close off. A consuming skill naming a member of its own that carries that property states that the member takes this exemption. That is a third obligation this chassis puts on such a skill. Having no other record neither admits a line nor rescues one. A line that fails the test stays off whether or not anything else records it. A one-record line no rule places, meeting the default's doubt, stays off too. Its standing as the only record is a reason for the consuming skill to place its class by rule, and never a reason for the default to admit it. That is an obligation this chassis puts on a skill built on it (the kind fork below states another): name by rule every class its ledger is the one record of. An unnamed one-record class is exactly the class the default loses. The naming is what settles the need for its members rather than what routes them around the test. What the test refuses in a withdrawn reading, a correction, or the story of how an instrument was found broken is the episode's narrative. What each leaves behind takes the rule that already places it, so the default never sees it. The reading a withdrawal replaced is a line whose held fact changed, and it is rewritten in place under supersede whether the watched thing moved or the instrument was wrong. Where a correction earns a ping under the ping template, that ping is a recent ping on the situational list. The trap a broken instrument taught is a do-not-reopen trap on the standing list, kept live by the prune rule however old it is. The reasoning that produced the trap goes where the destination rule sends a lesson about the watch's own instruments, the memory store. That is the split the prune rule draws when it says a trap outlasts its reasoning.

**The kind fork is decided on the cost of the misfiling, never on the kinds' names.** Doubt about which kind an admitted line is falls to the kind whose misfiling is the cheaper error. On this file's own two kinds that is the kind whose misfiling costs a re-measurement. The cost is the one the two kinds' own definitions state. Standing is what a successor acts on without re-measuring (the tick order's re-measure step reaches the condition a standing line cites, not the line). Situational is what a successor re-derives before acting on. Re-derivation is a probe of the watched system under the tick order's re-derive step, never a read of another record, whatever the line's provenance. That definition governs the doubt this fork decides and not a line the two-kinds rule has placed by name, since the fork is a tie-break for doubt alone. A recent ping sits situational by that rule though no probe of the watched system reproduces a sent ping. So a line filed standing wrongly is acted on stale, which is the failure this file exists to prevent, since the re-measure step in the tick order reaches only a standing line that cites a condition. A line filed situational wrongly is probed once more per pass than it needed to be, and carries what every situational sentence carries. On the two kinds above, doubt therefore falls to situational, with one class carved out and the carve-out asked first. Because it is asked first, a doubt spanning that class and situational takes the carve-out rather than the general rule. The class is the one that cost basis does not reach, a standing member no probe of the watched system reproduces. Of the standing kind's three members that is the prohibition and the do-not-reopen trap, and never the mechanism confirmed in the system's source, whose confirmation is exactly such a probe. Doubt about whether an admitted line is such a member falls to standing, for two reasons. Filing it situational costs no re-measurement, there being none to have. The error on the other branch is the cheaper one. A situational DO-NOT filed standing forgoes an act the watched system now permits, which a later pass or the operator's word can still take. The re-measure step reaches such a line wherever it cites a condition, and one citing none is obeyed stale until the operator's word retires it. A member filed situational licenses the act the line existed to close off, which no later pass takes back and no step of the tick order corrects. The two members fail differently. Re-deriving a trap is the re-opening it exists to forbid, so the misfiling commands the act the trap closes off rather than costing a measurement. The prune rule keeps a trap live however old it is on a cognate reason. A prohibition cannot be re-derived at all, since no probe of the watched system reproduces one. A successor holding it as situational therefore never satisfies the two-kinds rule's re-derive-before-acting requirement. The line is left standing as found, since supersede fires on a changed fact and nothing removes a line whose fact did not change. The re-measure step reaches only a standing line. The self-authored wake prompt under Wake mechanics carries the standing prohibitions and a pointer to the ledger, and nothing else. So a prohibition filed situational drops out of the wake prompt entirely and stops binding before any pass reads the ledger. A line the keeper recognises as either is standing by the two-kinds rule already. The carve-out reaches only the doubt. The fork is stated for these two kinds. A skill that replaces them states its own fork beside its override, on the same cost.

Every situational sentence carries two things: the time of the evidence behind it, and the command that re-derives it. A sentence with neither is a claim no later pass can check.

**Supersede in place.** When a fact changes, rewrite the line that held it. Never stack a new baseline under an old one and leave both readable.

A **read protocol** sits at the top of the ledger, stating what a constrained pass reads and in what order. A pass that cannot read the whole file still reads the parts that stop it doing damage.

**Prune on a quiet tick**, never on a busy one. Move superseded history to a dated archive byte-identical to what it replaced, and verify the hash at the destination rather than at the source. Keep the do-not-reopen traps live in the ledger however old they are: their whole value is that they outlast the reasoning that produced them. Re-derive any section offsets or line pointers after the last edit of the pass, not before.

## The tick order

The order is fixed. What a tick does inside the act step is the runbook's business and varies per system; the sequence around it does not vary.

1. **Ensure the heartbeat is armed first**, before any check, on any restart. This is the safety arm rather than the paced one step 4 sets, and its cadence is the runbook's to state. Session-only timers die with the session, so a loop that checks first and arms later is one crash away from silence nobody notices. A heartbeat already running satisfies this step; the move is to look, not to add a second.
2. **Re-derive the board** from the watched system's own source of truth. Never from the ledger, the handoff, or any situation text the wake prompt carries (a self-authored prompt carries none, by the rule under Wake mechanics; an operator-authored one may). Each of those is a hint with a timestamp, written by a pass that could not see this one.
3. **Re-measure before obeying.** For every standing DO or DO-NOT that cites a condition, measure the condition now, and re-read the governing document behind it. A plan doc outranks the ledger for that plan's gate: the ledger line was true when it was written and the plan changed under it.
4. **Act**, then **write the ledger**, then **ensure the next wake is armed**, then **sleep.** On a static board the heartbeat is that wake and nothing more is armed.

## Wake mechanics

A self-authored wake prompt carries the standing prohibitions and a pointer to the ledger, and nothing else. It never carries a situation report. Prohibitions age well; a situation does not. A stale armed instruction is worse than no instruction at all, because it will be followed by a pass with nothing to contradict it.

Check the timer list against the clock before assuming pacing is covered. A one-shot whose time elapsed during a long pass is stale rather than pending. It fires the instant the pass ends, which reads as a wake the loop did not schedule. Timers fire only while the session is idle, so a long attended turn defers the heartbeat; that is expected behavior, not a broken timer.

Pacing follows the board: a static board gets the heartbeat only, an active one gets a one-shot 15 to 60 minutes out. A board is active when something on it is expected to change before the heartbeat comes round again. A board you cannot confidently place is active, because the cost of the two errors is not symmetric. An unnecessary one-shot spends a pass, and a missing one spends the window the loop existed to watch.

## The ping template

A ping is what the loop sends the operator. Its parts, in order:

1. **Corrections to earlier claims, first.** Labeled as a correction, and sent at all only when the correction changes the shape of the operator's decision.
2. **The ask or the report**, in the client-briefing register, which the doctrine owns.
3. **The evidence line.** Every figure or state in the message names its source (the row, the column, the scan cycle it came from) and names its subject. A true number reported against the wrong subject is a wrong number.

Carry a **dedup key per condition**: one ping per condition, and never a re-send of an ask already pending. A loop that re-asks reads as escalation and gets the operator's attention for a question they already answered.

Two rules that govern a ping are owned outside this skill and are not restated here. When to escalate at all is the doctrine's "Pause only for a true blocker" bullet, under How we work, which points at the executing-work skill for the closed blocker set a ping may interrupt on. For what a measurement reads when its source is down, the doctrine's "cannot measure" line governs, under Verify before you claim.

## The one-way-door preflight

Before any closure, dismissal, delete, or resume on the watched system, name in one sentence what will act on the thing afterward. If the answer is "the mechanism this closure removes", do not close it. Those four are instances of the class: any action that removes the thing that would have brought the item back.

Killing a dispatched agent is that same door. The doctrine carries the habit (probe it with a message before any stall-signal kill, under Environment and tooling discipline). `finishing-work`'s unavailability rule owns everything the habit needs to fire: the wedge hallmark that authorizes a quiet-kill, the cadence that earns a probe, the windows for the classes it lists, and the rule for deriving one for a class it does not. That rule fires on a re-block, and a watch re-blocks on nothing, so the check is written into the tick order rather than triggered. Every pass with a dispatch in flight evaluates the hallmark. That pass reads those paragraphs first, at `skills/finishing-work/SKILL.md` under the plugin root (`CLAUDE_PLUGIN_ROOT` where the harness supplies it, else this skill's own base directory's grandparent), from the bold lead **Unavailability is the gate failing to run at full strength**. Derive a window from that rule; never invent one this skill does not own. The watch-specific part is that a loop staring at a quiet directory will manufacture the stall signal for itself, because quiet is most of what a watch ever looks at.

## What done looks like

A watch ends when the quiet streak runs long enough that the operator retires the loop. What it hands over then is a distilled list of what the interventions taught, split two ways: what the watched system should do for itself, and what the kit should stop the agent doing. The ledger is the raw material for that list, so write every pass in a form that survives distillation: the condition, what was done about it, and what it turned out to mean. That last is the fact of the watched system the pass established and never the keeper's reasoning toward it. The admission test refuses that reasoning under its second tell, and the destination rule below routes it where durable.

That hand-over serves a watch that ends; a lesson's home is reachable during the run either way. The destination rule names three homes. A decision about a plan goes to that plan's Chapters. A durable lesson about the watch's own instruments goes to the memory store in the pass that produced it, no plan owning it. The ledger keeps the pass record above and the current state, and nothing is written to the ledger twice. The current state is the ledger's own definition under The two artifacts, which the two-kinds rule above already divides into the members it places. On a watch with no scheduled end, a standing seat, that write-time routing is the whole mechanism: distil-at-retirement never fires on a seat that does not retire.
