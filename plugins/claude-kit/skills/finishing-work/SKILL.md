# Finishing Work

An effort is done when behavior is verified, security is reviewed, documentation matches reality, and the plan doc is closed. Run these steps in order. Steps 2 and 3 may be dispatched in parallel once step 1 passes. Step 4 runs once both have returned, and step 5 follows it.

When per-section reviews cleared parts of the changeset, tell the finishing reviewers what they covered and what changed since. Their budget then goes to cross-section cohesion and deltas rather than to cleared code. A round the rule aimed below Fable, or one that ended ungated, cleared nothing here, so step 3 reads its sections whole. Cut duplication, never coverage. For a small effort with no meaningful per-section reviews, fold the two advisory lenses into one adversarial dispatch carrying their scope, and never manufacture separate passes for a handful of files. A folded pass prints its performance and security findings under their own lens label. Those lines take step 2's advisory disposition and count nowhere on the adversarial verdict, so folding the dispatch never folds the route.

Dispatch every finishing reviewer at `fable` and effort `high`: the advisory reviews (step 2), the final adversarial review (step 3) and the document lenses step 3 runs. Each takes executing-work's capacity reading (its step 1) first. Step 4's goal read is the one exception and routes itself. The route is `Workflow`'s `agent()` on the Reviewer Dispatch template. Where Workflow is unavailable, use the Agent tool at `model: 'fable'` and frontmatter effort, recorded as lower-effort.

**Unavailability is the gate failing to run at full strength, with no decision behind it:** the round cannot run at its assigned tier, because the model is not reachable on this account or this environment would not run it there. Confirm it from evidence, never from an expectation that a model is missing. Two triggers confirm it, and they conclude facts of different strength: an error speaks about the model, a substitution about this round, and a stopped pair about this gate at this tier. Executing-work's capacity reading before a fable dispatch leaves this ladder live behind a reading that passes, since that reading is a prediction and this ladder is the observation.

**The first is an actual dispatch failure:** attempt the override and read the error. A harness that silently substitutes a model is this trigger with no error, so read the model the round actually ran at, per the resolved-model paragraph below.

**The second is a pair of consecutive stopped dispatches at the model in question:** the original and the one same-model retry this rule allows, each stopped by this rule in any shape. The model is the requested one, read from the dispatch record you hold: the override you passed, or the session's own model where you passed none. A never-started dispatch has no other reading, since its transcript carries no resolved model. The pair establishes a fact about the gate rather than the model: this gate could not be run at this tier in this environment, across both attempts. A retry cannot tell an exhausted allotment from one brownout stalling both attempts, so the pair never shows the model unreachable on this account. A stop at another model, or a lone first stop, says nothing about this tier and takes its dispatch class's own disposition.

The transcript's `.meta.json` sidecar cannot stand in for the dispatch record. It carries a `model` key only where an override was passed, so it is silent whenever a dispatch inherits, as a Fable-led session's Fable reviewers and `implementer-fable` dispatches do.

**The resolved model lives on the transcript's assistant lines, and the dispatch record carries the requested one.** It is the `message.model` value on the `"type":"assistant"` lines of `agent-<id>.jsonl`, under the session's `subagents/` directory, or under `subagents/workflows/<run-id>/` for a Workflow round. Read it line by line, never with a whole-file Read. Take it as a distribution, because substitution is not all-or-nothing across a run. Record the tally from a finished run, since its counts sum to the assistant-line count only once nothing more is appended, and a mid-run tally is diagnostic only. Report every distinct `message.model` value with its count, excluding the `<synthetic>` placeholder, which names no model.

Spell the reading as a per-line parse that prints one `message.model` value per assistant line and tallies them, never as a substring extraction or a grep that prints matches. A printed match pulls a whole turn into the session, and a substring match also counts model names quoted inside a turn. Use `node -e 'require("fs").readFileSync(process.argv[1],"utf8").split("\n").filter(Boolean).forEach(l=>{try{const o=JSON.parse(l);if(o.type==="assistant"&&o.message)console.log(o.message.model)}catch{}})' <transcript> | grep -v '<synthetic>' | sort | uniq -c`, or the host equivalent that reads one field per line.

Map the two vocabularies before comparing. The requested side is an alias (`fable`, `opus`), and the resolved side a versioned id (`claude-fable-5`, `claude-opus-4-8`, `claude-opus-5`). An id satisfies an alias when it carries that family's prefix or a stronger family's, so neither a version difference nor an upward substitution loses tier. A dispatch that passed no override is compared against the session's own model.

A tally with zero counts satisfying the requested alias, and at least one parsed non-synthetic line, is a round that never ran at its tier, and it takes trigger one. The bound makes the zero mean a model that answered as another model, not one that has not answered. An empty tally never reaches this branch. Where the `<synthetic>` count accounts for every `"type":"assistant"` line, it routes to the never-started paragraph below. Where the assistant lines outnumber that count, the parse found no `message` object, and the distribution is unreadable.

An `undefined` entry is the parse missing `message.model` on that line, so it names no model and enters no comparison. A tally mixing `undefined` with parsed entries is read on the parsed entries alone. Only an all-`undefined` tally is unreadable rather than a substitution, so a moved field never fires trigger one against a healthy run.

A distribution mixing the requested model with another ran at its tier for part of its length. It is not unavailability and never enters the ladder, since the ladder's compensation may be weaker than the mix. Record it in the final Chapter and the close-out status as a partial substitution, stated as a proportion, and let the round stand. No threshold splits the mixed case. The close-out names a majority-substituted round as one that ran mostly below its tier, so the operator decides whether to re-run it. A compensating dispatch whose own distribution is mixed is recorded the same way, never compensated again.

**The wedge hallmark rests on the probe, and the other two observations bound it.** A dispatch is wedged when all three hold. Its status still reads `running`. Its liveness reading has shown no sign of life for the window its shape sets, or that window has elapsed since dispatch with no usable reading. It has not answered a `SendMessage` probe within the probe window its shape sets.

The shape picks the reading and the windows. A dispatch that has taken a turn is read on byte growth, against its class's growth and probe windows. One whose pair of counts, per the never-started paragraph below, reads both zero is read on that pair, against the five-minute first-turn and probe windows. One whose instrument is unreadable is read on elapsed time since dispatch, against its class's windows. Once a probe is away, the reading is the non-synthetic assistant-line count wherever the transcript is readable, whatever the shape.

Short of all three observations, a quiet running dispatch is working. Nothing short of the whole hallmark authorizes killing any dispatch **for being quiet**, and every dispatch site points here rather than restating it. A kill on other grounds, such as a brief invalidated mid-flight, a tree-mutating probe or a deliberate replacement, is executing-work's TaskStop with no window to wait out. This rule's own such kill is the stop-first TaskStop before the synthetic-only fault's re-dispatch, which the never-started paragraph below mandates.

**Transcript growth is a short-circuit, never a second vote on liveness.** Growth inside the class's growth window proves the agent took a step and ends the inquiry with no probe spent. A probe answer is itself an append, so a zero corroborates nothing. The growth reading is a byte reading, taken without reading the file. Growth counts with no assistant line in it, since a healthy run appends tool results as `user` lines between turns.

The one exclusion is the synthetic-only shape. Where no turn is yet established, qualify growth with the never-started paragraph's pair of counts, a separate cheap read, never by inspecting the grown bytes. A zero non-synthetic count beside a non-zero `<synthetic>` count makes the growth the fault's placeholder rather than a step. That shape routes to the never-started re-dispatch at the first-turn window's close, never before, on the timing the cadence paragraph below sets.

The growth window opens at the last observed growth, or at dispatch where none has been observed. The byte reading retires at the probe send, so the probe's own append never reopens it. From the send on, liveness is a rise in the non-synthetic assistant-line count above its value at the send. That count sees an answer, which is an assistant turn, and ignores the probe's `user` line and any tool result's append, so neither a swallowed answer nor either append misleads it.

**A zero-growth reading is an absence-proving check and earns its silence the same way any other does.** Read it at the agent's own transcript, at the path the resolved-model paragraph above spells. The `.meta.json` beside it names the agentType, plus a `description` and `toolUseId` where the dispatch carried them. Dispatches of one agent type write byte-identical sidecars, so tell a fan-out's transcripts apart by the dispatch record you hold. Never measure at a task's `.output` path, which reads zero bytes for a healthy agent and a dead one alike. Read the byte count without reading the file: .NET IO through PowerShell on Windows, and elsewhere whatever reads a size without contents.

The harness creates the transcript at dispatch, at a path set by the session's subagents directory and the agent id. So where you hold both and find no file, the instrument is unreadable rather than the agent idle. Where either is unknown there is no reading, and a reading a control contradicts is no reading either. Before a zero counts, show the instrument observing growth at a live sibling, one whose byte count moves between two readings. A bare non-zero size is no control, since the transcript holds the prompt from dispatch. Where no control is available, the ordinary case for a lone early dispatch, the instrument is unproven rather than the agent dead. On an unproven or unusable instrument, take elapsed time since dispatch for the same window, go to the probe, and record the growth reading as unavailable.

Probe an Agent-tool dispatch at its task id. Probe a Workflow round's agent at its agent id inside the run directory, since `SendMessage` to the run's own task id reaches no agent. Where the agent id cannot be recovered, the probe can never be sent, and waiting on it is the multi-hour wait this rule exists to end. So at the close of the elapsed-time fallback's two windows, with status still `running`, TaskStop the run's own task id. That ends the whole round, so first let every other dispatch in it complete and have its output read. The stopped dispatch enters the ladder below like any other stop, its shape recorded as diagnosed on the fallback with the probe unsendable.

**A dispatch that never took a turn is its own shape, and the transcript names it.** Byte growth cannot see this shape. The transcript exists from dispatch, at the path the resolved-model paragraph above spells, its first line a `user` line carrying the prompt and stamped with the dispatch time. A dispatch that never takes a step holds `user` lines only and reads as a stall for the whole growth window.

The reading is a pair of counts over the `assistant` lines: those whose `message.model` is not `<synthetic>`, and the `<synthetic>` lines themselves. `<synthetic>` is the harness's placeholder for an API error mid-response, not a turn. Route on the pair, because the non-synthetic count alone returns the same zero for two shapes that take opposite actions. Both counts zero at the first-turn window's close is the never-started shape. A zero non-synthetic count beside a non-zero `<synthetic>` count is a transient fault, a dispatch that reached the API and failed mid-response. Its first remedy is a re-dispatch rather than the ladder's downgrade.

That re-dispatch takes the stop-first rule every replacement takes, since the faulted dispatch may still read `running` and a racing successor puts two agents at one brief's files. It spends the ladder's one same-model retry rather than adding a second. Where this rule stops the successor in its turn, whatever its shape, trigger two above is met and the dispatch enters the ladder below at its class's route.

Read the control before any zero counts. The counting pipeline prints a bare `0` for a missing path and complains only on stderr, so a wrong path reads as a real zero. The control is a count of `"type":"user"` lines in the same file, which prints no count at all for a missing path. A non-zero control proves the path and the line-type pattern, and nothing about the `<synthetic>` spelling. So claim no more than the counts deliver: a renamed placeholder inflates the non-synthetic count, masks a synthetic-only fault, and can fire trigger one against a faulted dispatch.

Tie a transcript to its dispatch by the agent id from the dispatch record, never by the prompt text. One agent type's fan-out writes byte-identical sidecars, so a transcript picked by content can return a sibling's non-zero.

Where the instrument is unreadable, the id unknown or no file at its path, the shape is unestablished. The fallback is the growth reading's own: elapsed time since dispatch against the class's growth window, then its probe window, with the first-turn reading recorded as unavailable. Where the probe is unsendable, a Workflow dispatch whose agent id cannot be recovered, the zero-growth paragraph's run-level stop owns the close of those windows. The short windows are earned only by evidence this reading produces. A healthy agent inside a first tool call longer than five minutes cannot answer a probe either, so a guessed short pair would stop a live agent and discard its work. A wedge diagnosed on this fallback still counts toward trigger two's pair.

Take both counts line-filtered and spelled as counts, never as a whole-file Read, since printing one assistant line pulls a whole model turn into the session. The non-synthetic count is `grep -a '"type":"assistant"' <transcript> | grep -acv '"model":"<synthetic>"'`, and the companion swaps `-acv` for `-ac`, or the host shell's equivalents. Every grep over a transcript takes `-a`, because a NUL byte flips grep into binary mode and its one-line notice passes the `-cv` filter as a turn.

**Evaluate the hallmark on a cadence rather than on a suspicion**, for every in-flight dispatch whatever its model. A wedge sought only on suspicion is the multi-hour wait this rule exists to end. The wakes are three: the completion notification for any dispatch the `WAITING:` line named, a timer wake the session armed, and the session's first return to that dispatch after either, before anything else is done with it. Take the first-turn reading at the first wake at or after the first-turn window closes, and at every wake after. A non-zero non-synthetic count settles it whenever taken, since a real turn ends this shape.

Neither a synthetic-only pair nor a both-zero pair routes anywhere before the first-turn window closes, wherever in this rule it is read. The synthetic-only route opens with a TaskStop, which could otherwise land on a run about to recover. For a dispatch carrying a model override, take the first-turn reading at that wake whatever woke the session. Send the probe at the first wake that finds the shape's window closed flat, and run the probe window from that send.

A window is observed only at a wake, so land the wakes where the windows close. A session that can wake itself on a timer arms one for the class's growth window before the `WAITING:` turn end. It re-arms at every later wake that leaves a window open, the probe window or a pending first-turn window. A timer is armed for a named dispatch and never waited on alone, so the `WAITING:` line always names a dispatch. Without a timer the completion notification is the only wake, and a wedge produces none, since status reads `running` for healthy and wedged alike. It surfaces at session start and to the doctor, where the armed goal stays visible, and the operator's re-arm is the recovery.

A synchronous dispatch (`run_in_background: false`) holds the session inside one tool call, where no probe can be sent and no status read, so it is diagnosed after it returns. Executing-work's completion contract recommends that shape only for a single critical-path implementer and refuses it to any dispatch carrying a model override, and whether to take its trade is executing-work's call.

**Set the windows from the asymmetry, which runs one way.** A TaskStop on a live agent discards everything it built, while waiting on a dead one costs only time. So err long everywhere and longer still for an unfamiliar class. A review-class dispatch is a read-only advisory one that appends at every step and runs no build by charter, the reviewers, readers, consultant, council member and design facilitator, and any later charter of that shape. Its growth window is fifteen minutes and its probe window twelve. The `qa-verifier` and the `docs-curator` are not review-class, since the verifier blocks inside its suite loop and the curator writes for long stretches. Their growth window is thirty minutes and their probe window twelve. Any other non-review class sets its windows from its own cadence, with at least that much room.

The never-started shape has no such asymmetry, since an agent that built nothing has nothing to discard. Its short pair is shared by every class. The first-turn window is five minutes from the dispatch time the session holds, or, where that time is not to hand, from the transcript's first `timestamp` field, read as `head -1 <transcript> | grep -ao '"timestamp":"[^"]*"' | tail -1`. At that window's close with both counts zero, send the probe, and the probe window is five minutes from that send. At its close with both counts still zero, TaskStop and enter the ladder below, which re-dispatches once at the same model. Where this rule stops that re-dispatch in its turn, trigger two above is met, on these short windows if it too never starts and on its own shape's windows otherwise.

The short windows rest on a measured harness property: the transcript appends an assistant line when a turn is produced, not when its first tool result returns. On a healthy dispatch the tool-call line sits 69 s ahead of its result's line. Without that property, an agent in a long first tool call would read as zero turns and be stopped at the 600 s kill point.

**What follows a TaskStop is the wedged dispatch's own class.** Every class gets one same-model re-dispatch first, because a first stop is a suspicion. Where the retry runs, nothing is recorded against the model. The retry is one whatever route spends it. Where this rule stops it in its turn, the pair meets trigger two whatever the two shapes. No chain reaches the third same-model dispatch executing-work forbids. The record below names each dispatch's shape.

A review-class pair compensates rather than falls back, per the route below, and a per-section reviewer aimed below Fable re-aims one tier up per executing-work's rule instead. Compensation is open only at a tier the chain has not ruled out. A pair stopped at opus gets nothing from it, since the compensating dispatch and the bare fallback are both opus. That round ends ungated, recorded with the chain and each shape and surfaced in the close-out.

The compensating dispatch is the ladder's last rung. Whatever ends its route ends the round, trigger one or its own trigger-two pair, and it never re-enters the ladder. Record the step as ungated in the final Chapter, naming the shape that ended the round and every wedge, stall, fault or substitution in the chain.

A stopped `qa-verifier` or `docs-curator` retry hands its step to the orchestrator, which runs the step's own commands in the main thread and records it as self-run. The step is ungated only where the main thread cannot run them either. A read-only scout returns leads rather than a gate, so re-dispatch it or drop it, naming the gap in the Chapter. Every other class returns to its own skill's ladder, executing-work's for an implementer, since compensation is a gate instrument.

**Compensating.** Re-dispatch through `Workflow`'s `agent()` at `model: 'opus'` and `effort: 'max'`. Name `agentType` as the scoped agent the dispatch being compensated ran as, whichever reviewer that was (`claude-kit:adversarial-reviewer`, `claude-kit:security-reviewer` and `claude-kit:performance-reviewer` the common three). Fill executing-work's reviewer-dispatch template, whose three fields are required. The doctrine's standing-dispatch bullet carries the operator's request for this route, so it needs no per-session ask. Await the round as executing-work's completion contract awaits any dispatch, by the `WAITING:` turn end. Keep it one round under this skill's single tree-state capture. A folded whole-changeset pass is an `adversarial-reviewer` dispatch, so name that `agentType`. Compensate only the dispatches that failed, judged one at a time.

**The bare fallback** applies where fable is ruled out and Workflow is unavailable too. It is an Agent-tool dispatch at `model: 'opus'` with the reviewers' frontmatter effort, and its record names both losses, tier and effort. Never drop to the session model while an Opus override is available.

Record the compensation or fallback in the final Chapter with the trigger that led to it, the shape of each stopped dispatch, and the evidence. Name it again in the close-out status, so I can decide whether to re-run the gate where fable is reachable. A compensation reached by executing-work's capacity reading records the reader's line verbatim instead. The evidence is the verbatim error, the `message.model` distribution with counts for a substitution, or the `<synthetic>` count pair for a synthetic-only fault. For a wedge it is the dispatch, how long it read `running`, and the unanswered or unsendable probe, plus its liveness reading. That is the artifact showing no growth or the reading unavailable, the zero pair at the first-turn close, or the elapsed time on the unreadable-instrument fallback.

Say whether you compensated or fell back, because the model alone does not tell a reader. A compensated gate climbed its effort to cover the lost tier, while a bare fallback left the loss uncovered. Never let an unavailable gate pass unremarked: a downgrade nobody chose is exactly what a close-out exists to surface.

**Bracket steps 1 through 4 with the tree-state check.** Capture `git status --porcelain` before dispatching each of those rounds and compare when the round returns, before acting on any finding. A delta is the same incident executing-work's review rule names, with the same consequences, recorded in the final Chapter.

The check compares two porcelain readings, not the bytes on disk, so it misses any write that leaves no tracked-file delta. That includes a write to a gitignored path or outside the git root, a new empty directory, and a mutate-read-restore inside one round. The check also misses any act moving HEAD and the worktree together, a merge, `checkout`, `pull` or `reset --hard`, and any act outside the worktree, an outward `gh` mutation, a push or a tag. Those rest on the guard alone.

Git's ref, config and remote plumbing rests on nothing, since the guard treats it as review work: `git fetch`, `git remote`, `git config`, `git notes`, `git replace` and `git reflog expire` among them. So a refspec fetch writing local refs, a repointed remote, or a global config alias passes unwatched. Step 5 stays outside the bracket, since the docs-curator's edits under `docs/` are its deliverable and bracketing them turns its own output into a phantom incident.

**The finishing pass has one compaction boundary rule, and this is it.** No section closes during finishing, so executing-work's step 8 never fires. The trigger is the compaction gate's own recorded deferral, which needs no count: `compact-deferral-nudge.js` firing between finishing steps, or a step's adjudication finding the gate holding offers, per `kit-compact-checkpoint.js status`. On that signal, append `### Interim board N - YYYY-MM-DD` to the plan doc with the content shape executing-work names for it, honor the commit model for the doc, and run `kit-compact-checkpoint.js open`. Take the boundary whenever the signal stands rather than once per pass.

## Steps

**Establish the effort's base ref before step 1, unconditionally.** This is the pass's opening move, outside every step. Record it in the final Chapter and hand it to every dispatch and read that follows. Under Review-Only the base is `HEAD`. Under Branch-and-PR it is the merge-base of the working branch with the integration branch. Under Commit-and-Push it is the parent of the earliest commit that appended a Chapter to the plan doc.

Under Commit-and-Push, walk `git log --reverse --format=%H -- <plan path>` and take the first hash whose `git show --format= --unified=0 <hash> -- <plan path>` output matches `^\+### Chapter `. The base is that hash's parent, resolved to a sha at derivation time (`git rev-parse <hash>^`) and recorded as the sha rather than as the caret expression. Where that hash is the repository's root commit, the base is the empty tree (`git hash-object -t tree /dev/null`). Where concurrency put a Commit-and-Push session on a worktree branch, the base is the merge-base with the integration branch instead. Where no commit has appended a Chapter, the base is `HEAD`. Never derive it from the commit that added the plan doc.

A wrong base raises no error, so check it before spending it. Take step 5's changeset listing against it and compare that listing one-directionally with the union of the plan's `Files in scope:` lines. Surface only the entries outside both that union and the bookkeeping set, which is the plan doc and the docs index (`docs/README.md`). Three further classes are expected surfacings rather than a wrong base: a sibling session's commit landed after the base, a persistent untracked file the repo does not ignore, and a plan with no `Files in scope:` lines. Equality is never the test. The listing holds the plan doc, and a scope line may name a non-path entry such as a memory tier.

1. **QA verification.** Dispatch the `qa-verifier` agent with the spec path: full build, full test suite, and every acceptance criterion checked with evidence. **The brief carries the contention lane's own command, or states that this repo defines none.** On any FAIL, fix and re-run before proceeding. Never rationalize a failing criterion as "close enough".

   **That full-suite run is the first of two whole gates, not the only one.** The whole gate runs again after the last step that changed the tree and before step 7, and the plan hands off on that later run.

   **The contention lane runs beside each of them, and beside every other whole gate this pass runs.** The re-run's counts, its exit code and the contention lane's are the handoff's evidence. Step 6 records them in the final Chapter's `Gate:` line, which it writes open ahead of the re-run and fills afterwards. The handoff earns no gate beyond the re-run. Step 7's merge and install-surface push earn theirs on their own conditions, named at that step.

   An UNVERIFIABLE criterion splits on who could ever verify it. Where the blocker is environmental, such as a missing database, runner or secret this session could supply, fix the environment and re-run. Where only I could ever verify it, it is neither a FAIL nor yours to close. Confirm the reason is genuinely operator access rather than effort, then carry the item into the step 6 handoff. Operator-only means no environment work available to this session could exercise the path.

2. **Advisory reviews.** Dispatch the `performance-reviewer` and the `security-reviewer` agents over the whole changeset, not just the last section, at `fable` and `high` by the route above. Send them in one `agent()` wave with step 3's adversarial lens. The step numbers order the reading of the returns rather than the dispatch. Findings take the advisory disposition executing-work's step 4 states (`skills/executing-work/SKILL.md` under the kit plugin root). Write them on this pass's interim board entry in place of that paragraph's section advisory list, since this pass has no Chapter until step 6. A fix-now lean takes that paragraph's relevance ruling before the fix is written, and a cited security Critical takes it whatever the lean. Where the security lens opens its report `threat model: absent`, carry "write the threat model" to the plan's `## Operator Verification` section as an operator-pending item on step 6's route, and to `docs/backlog.md` so it survives the archive. An advisory lens blocks this pass in two cases, each fixed before the close or raised to me. One is a cited security Critical the ruling confirms. The other is a `Disclosure:` sweep hit, which blocks with no citation and no ruling behind it. This pass reads that hit as a correctness Critical wherever its fix path's exits read one, so the round backstop never freezes it and the fix path cannot end while it stands. Every other advisory Critical or Major is fixed, deferred or refused with its reason on that entry, and blocks nothing. A Critical from step 3's correctness lens routes on the fix path below, not here. One waiver exists, on two predicates rather than a judgment call. The first holds when every file in the changeset is prose: markdown or plain text, with no code, script, hook, config, query or schema file. The second holds when no document in it is written for an audience outside the operator and the operator's own sessions. When both hold, both dispatches may be skipped, with the skip and the changed-file evidence recorded in the final Chapter.

   **Markdown whose frontmatter is machine-read is not prose for this predicate.** An agent charter under `agents/`, a skill's `SKILL.md` and anything under `.claude-plugin/` are configuration, whatever their extension. A single non-prose file, even a one-line edit, voids the waiver. Then run both reviews, scoped to the non-prose files when the rest is prose.

   Read the audience predicate off the spec's `Audience:` lines rather than off the documents, since a document states its content and not its audience. **The spec alone holds the waiver, and either source voids it.** A document that names or addresses an outside audience on its face voids the waiver even where its spec section is silent. Run the security lens with the spec's `Disclosure:` list in its brief and the instruction to sweep the documents in scope for any item on it. The sweep is that lens's alone, and a hit is the one Critical that blocks with no threat-model citation and no ruling behind it.

   **An owed Major on this pass's fix path is fixed, or presented to me with the tradeoff.** That fix-or-present rule is the pass's route for such a Major wherever on the path it entered. It never reaches a new-requirement Major, which takes the hold and judge below, nor an advisory finding, which takes step 2's disposition.

   A fix round this pass runs, here, at step 3 or on step 4's items, ends on executing-work's terminal condition (`skills/executing-work/SKILL.md` under the kit plugin root, step 4's `The loop ends on the class of what remains`). It stops on that step's review-round backstop, counted over this pass's own rounds. One round is this pass's review dispatches taken together: the advisory lenses where step 2's waiver did not skip them, the adversarial lens, and the document lenses where those run. Each further round the fix-delta bar owes counts too, whatever lenses it carries. A fix delta from step 4's items takes the adversarial lens alone, over that delta and on that same re-dispatch. Neither advisory lens joins a fix-delta round, since the bar's rounds are the correctness tier's. So a fix delta written after step 2 gets no advisory read, the loss executing-work accepts on a decayed round. The goal read is not re-dispatched over a fix delta.

   This round unit is executing-work's own: a round counts once the roster its round rule dispatched has returned, and a later round's one lens is such a roster. The two share the bound and the exits, with the changeset the base ref defines standing where that skill reads the section's files.

   That step's provenance read runs over this pass's owed Majors too, on the same three values.
