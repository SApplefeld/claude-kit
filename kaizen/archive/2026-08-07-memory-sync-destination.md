# Kaizen brief: the memory-sync check must prove the store syncs somewhere

Friction: the doctor's memory-sync section proved what the store may publish and never that there was anywhere to publish it to. All four leak probes read clean on a store with no remote, on a branch tracking nothing, and on a store whose origin carries a branch name this machine does not track. The last is silent in both directions: push and pull each succeed, neither reports anything, and no machine ever sees another's memories. A no-remote store reported PASS with the fact buried in a detail line, which is the state a green section most misleads about.

Change:
- `plugins/claude-kit/doctor/install-memory-sync.ps1`: `Get-MemorySyncStatus` gains `Branch`, `Detached`, `Upstream`, `RemoteBranches`, and `DestinationRead`, read from local refs only, so the answer costs no network and is as of the last fetch. `refname:short` renders `refs/remotes/origin/HEAD` as the bare remote name, so both that and the unshortened form are dropped; counting either reports a divergence on every healthy store.
- `plugins/claude-kit/doctor/doctor.ps1`: `Get-MemorySyncDestinationLines` splits the states by what an operator choice can explain. Blocking (FAIL): a detached HEAD, a branch tracking nothing, an upstream on some other remote. Advisory (WARN): a second branch on origin, which is the reported silent case but which a backup or abandoned branch also explains, so it is named rather than failed on. No remote is its own WARN with the remote-add fix line, replacing the PASS detail. A healthy store's PASS now carries a Destination line naming the branch, its upstream, and that it is the only branch on origin.
- `test/memory-sync.test.js`: one new case driving all four states against a bare repo on disk (a real remote for every read this check makes, so no network and no credentials), plus the two existing expectations that asserted PASS on a remoteless store.
- The three consumers that gated on the old report values, moved with it, because a new WARN would otherwise have silently blocked a legitimate push. `finishing-work/SKILL.md` and `memory-system/SKILL.md` said "push only once that run's memory-sync line reports PASS or FIXED"; both now split WARN by kind, since the destination warnings are reported only after every leak probe reads clean and so keep the allowlist guarantee, while a probes-did-not-run WARN is a stop like a FAIL. `hooks/memory-session.js` restated the same predicate in its session-start nudge and now points at the skill instead of carrying a copy that would rot again, with its exact-string pin in `test/memory-session.test.js` updated to match.

Acceptance: baseline 670 tests, 668 pass, 2 fail (the pre-existing memq-shim pair filed in docs/backlog.md); after, 671 tests, 669 pass, the same 2 fail, delta zero. The two updated cases were watched failing against the new code before their expectations moved. The new case was proven non-vacuous by a tree-mutating probe: dropping the bare-`origin` filter makes the report read "carries origin, origin/other-machine" and the anti-phantom assertion fires.

One branch is deliberately beyond the suite's reach. The terminal PASS asserts the tracked branch is the only one on origin, and that claim rests on having read origin's branches, so it is gated on the read having answered. Upstream resolution goes through the remote-tracking ref, which means a pruned or never-fetched origin drops the branch to "tracks no upstream" and reaches the blocking path first; the empty-set-with-an-upstream state is therefore unreachable, and only a `for-each-ref` that errors outright can land on the guard. The suite pins the reachable ordering (deleting the tracking refs yields the no-upstream FAIL and no sole-branch claim) and the guard stands unexercised, on the same reasoning the file already applies to its leak probes: a probe that did not answer is not a clean result.

Discipline: severity calibrated so the check stays readable. A FAIL exits 1, so it is reserved for states no operator opts into; a stale backup branch that failed the run would teach the operator to stop reading the section.
