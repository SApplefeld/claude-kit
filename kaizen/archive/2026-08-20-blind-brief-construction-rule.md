# Kaizen brief: the blind dispatch in a multi-agent script is built, not filtered

Friction: when several reviewers dispatch from one Workflow script, the natural JS shape is a shared const holding the section's context, reused across the reviewer prompts, and that shared const is exactly the intent story the blind contract excludes. In the observed run the blind reviewer caught its own contamination and said so (the charter working, the round spent). The 2026-08-17 brief made the property test lead the withhold list; this incident shows the test can lead and still lose, because it judges content while the leak arrives through construction: the author composes dispatches from shared parts and contaminates before any content test is applied. General lesson: a contract stated as what the artifact must not contain loses to the convenient construction path; the durable form is a build rule stating how the artifact is assembled.

Change: `plugins/claude-kit/skills/executing-work/SKILL.md`, the paragraph after the Reviewer Dispatch template (the Workflow route): add the construction rule. In a script assembling several dispatches, each blind prompt is authored as its own literal, composed of the blind boilerplate plus its contract inputs (base ref or changed-file list; document paths and Reader: line for the blind-reader) and nothing else, sharing no brief-building constant, helper, or template variable with any sighted dispatch; the property test judges the assembled string each agent will actually receive, never the ingredient list.

Acceptance: the Workflow-route paragraph carries the build rule as a positive recipe (what the blind prompt is composed of), not a prohibition list; the step-3 blind contract and the Aug 17 test-leads placement are unchanged; suite at baseline (2 failing, both memq-shim environment-driven).

Discipline: follow writing-skills; baseline-test any behavior-shaping wording.
