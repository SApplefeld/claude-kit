# Kaizen brief: re-load skills and deferred tools after a compaction

Friction: on a 12-hour two-plan run (NEO-CLAUDE, relayed 2026-08-17), the compaction gate's safety valve landed a compaction mid-section, and the copy of executing-work left in context afterward was a summary that kept the top of the section loop (step 0, checkpoint clear; step 1, dispatch) and lost everything below the cut (reviewer tier bump, security-reviewer predicate, step 8 checkpoint open). The session ran that half for four sections: reviewers a tier low, no security pass on an external-boundary section, and no checkpoint ever opened, so the gate held to the valve every time. Nothing in the kit said to re-load: the compact-source SessionStart text said "follow the executing-work skill", and the skill's own recovery line mandated re-reading the plan doc and nothing else. The operator has seen the same shape in Discord relay tools going quiet late in long sessions, which is the deferred-tool-schema face of it. General lesson: what a tool call loaded into context is not a durable artifact; a compaction keeps the doctrine and the plan doc and drops the rest, with no marker where a summarized skill was cut.

Change: three surfaces, in the order a compacted session meets them. (1) `plugins/claude-kit/hooks/session-start.js`: on the `compact` source alone, emit a leading re-load block whether or not a plan is in progress: re-invoke the governing skill through the Skill tool, re-load deferred tool schemas through ToolSearch, treat a truncation marker inside a loaded skill the same way. (2) The doctrine's durable-artifacts bullet, in both copies (`plugins/claude-kit/skills/operating-instructions/SKILL.md`, `home/claude-kit-doctrine.md`): one sentence stating that loaded skills and tool schemas are not durable and what to do after a compaction, since the doctrine is the one text that is re-injected. (3) `plugins/claude-kit/skills/executing-work/SKILL.md` "Before starting (or resuming)": re-loading this skill is as mandatory as the plan-doc re-read, with the concrete failure named (step 0 without step 8). Docs: `docs/architecture.md` SessionStart line. Backlog: the step-8 mechanization candidate parked with its deciding signal.

Acceptance: `test/session-start-compact.test.js`, three tests watched red against the pre-change hook (2 of 3 red; the no-block-on-startup test passes either way by design) and green after; doctrine parity green; whole suite at baseline (952 tests, 950 pass, 2 pre-existing memq PATH failures unchanged).

Discipline: follow writing-skills; baseline-test any behavior-shaping wording.
