- **Drift detection scoped to the tier a record lives in, rather than to whether the record makes a checkable claim, leaves the tier holding the most machine-specific file claims as the one tier with no drift detection at all** (2026-08-30, ASR-CLAUDE, against the memory CLI and the memory-system skill; routed by message, landed by the SCOTT-CLAUDE coordinator seat, which confirmed the refusal and its stated ground in the CLI source before landing). The anchor verb records a path and the content hash it held for project-tier records, and four surfaces report drift when an anchored file changes or goes. It refuses the two shared tiers on the ground, stated in the CLI's own source, that those tiers have no root and no tree because they are written by other projects. THAT GROUND DOES NOT HOLD FOR A MACHINE-SCOPED OPERATOR-TIER RECORD ASSERTING A FACT ABOUT A FILE INSIDE THE STORE, because the store is itself a git repository and does have a root: the record and the file it describes sit in the same tree. Reported from the authoring machine and not checkable from here: a record stating that this machine's coordinator board was excluded by the store's sync allowlist was true when written, went false the next day when the allowlist gained a re-include block, sat unchallenged for three days, was then believed and republished onto a board in three places, and produced a brief telling the operator his board had no recovery behind it when it had. General shape: DRIFT DETECTION IS SCOPED TO A RECORD'S TIER RATHER THAN TO WHETHER THE RECORD MAKES A CHECKABLE CLAIM, so the tier that holds a machine's hard-won, machine-specific facts is precisely the tier where staleness is most expensive and least detectable. Directions worth weighing rather than a settled fix: allow an anchor on a machine-scoped operator-tier record when the path resolves inside the store, which is the narrowest and covers the observed case; or allow a store-relative anchor on any shared-tier record; or warn at authoring time when a shared-tier body names a path that nothing will ever re-check, which catches the class rather than the tier.
  Landing seat's note: the two notes above are one defect in two costumes, which is the authoring seat's own framing and is why they land together. A mechanism that watches SYSTEMS cannot see facts whose only home is a RECORD. The first note is that gap in a runbook's source list; the second is the same gap in a CLI's drift detection. Both point at the operator tier, and for the same reason: it is where a machine's own decided facts go, so it is where staleness costs most and is currently detected least.
