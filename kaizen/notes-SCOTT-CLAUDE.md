- 2026-08-16 | SCOTT-CLAUDE | sapplefeld-channels | A guard that decides by path *pattern* rather than by path *containment* fires outside the tree it means to protect. The docs-write guard's `isDocsPath` (`plugins/claude-kit/hooks/docs-write-guard.js` line 61) is `/(^|[\\/])docs[\\/]/i` against the raw argument, so any absolute path anywhere on disk with a `docs/` segment is a hit: a subagent writing a scratch file under the session scratchpad (`.../Temp/claude/<project>/<session>/scratchpad/docs/plans/x.md`) is blocked, and the denial text tells it to write to `.kit/` instead, which is advice about a repo the path was never in. The general lesson is the one to encode: a guard whose whole purpose is "keep writes out of *this project's* curated tree" must resolve the target against the project root and test containment, so that paths outside the root are structurally out of scope rather than incidentally matching. The narrower framing (special-case the temp dir) is the wrong fix, because the next false positive will be some other out-of-tree path with a `docs/` segment - a dependency checkout, a sibling clone, a mounted share. Note that the guard's own header comment (lines 13-18) already frames its heuristics as deliberately over-broad on *command shape*, which is defensible; over-broad on *location* is a different axis and is not argued for anywhere. RED probe shape: hand a non-curator subagent a write to an absolute out-of-repo path containing a `docs/` segment; correct behavior is allow, failure signature is the block. Origin: a QA verifier hit it mid-effort writing a report to a scratchpad path.
- 2026-08-16 | SCOTT-CLAUDE | sapplefeld-channels | A CLI that rejects input on an argument-count check should report the count it actually parsed, not only the shape it wanted. `memq`'s `usageCount` (`plugins/claude-kit/scripts/memq.js` lines 1554-1562) prints a targeted, genuinely excellent diagnostic for exactly one splitting cause - an argument containing a literal `"`, the PowerShell case - and for every other cause falls through to a bare usage line naming the expected shape (`add-operator needs <name> "<description>"`). When the split came from something the special case does not cover, the caller sees a usage dump that describes an invocation they believe they made, with no way to see what the process actually received; the failure looks like a mysterious length or content cap and costs a bisect through throwaway records to localize. The fix is cheap and general: echo the parsed positionals (count, and each one bounded to some display width) alongside the expected shape, so *any* splitting cause is self-evident from the first failure rather than only the anticipated one. This applies to every kit CLI that shells out to a positional contract, not just `memq`, and it generalizes past argument parsing: whenever a check rejects on a computed property of the input, the diagnostic should name the computed value, not only the expected one. Origin: five throwaway `test-probe-*` operator records created and deleted while bisecting a rejected `add-operator` call, whose real cause was never the length I first blamed.
