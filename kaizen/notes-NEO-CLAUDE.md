The judgment sidecar scores a tool call's output against the intent string the caller stated, so it raises a divergence alert on every DIAGNOSTIC whose whole purpose is to find divergence. For those calls a mismatch between expectation and result is the success condition rather than a fault, and the sidecar has the sign backwards: it alerts loudest exactly when the instrument is working. Reproducible class rather than an incident, confirmed by repeat firings on the same shape, both on the coordinator board's mandatory duplicate-subject sweep, whose entire job is to compare per-line expected occurrence counts against actual ones and surface the ones that differ; on one of those occasions the sweep had just caught a real self-contradiction on the board, so the false alert sat directly on top of a true positive. The cost is calibration rather than a bad act: a seat running a verification ritual every pass draws a guaranteed false alert every pass from the instrument that exists to flag its mistakes, and a channel that cries wolf on schedule is one a seat learns to skim, which matters because the true positives arrive through that same channel. Candidates: let a caller mark an intent as a divergence-seeking check so the sidecar scores whether the check RAN correctly rather than whether results matched expectations, since a check stating expected values inline is announcing it expects some to fail; or have the sidecar treat a stated expectation as a hypothesis under test rather than a prediction of the output. The general lesson: an oversight instrument that infers success from "output matched what the caller predicted" will systematically misjudge every tool whose function is to discover that a prediction was wrong, which is most of the verification surface.
