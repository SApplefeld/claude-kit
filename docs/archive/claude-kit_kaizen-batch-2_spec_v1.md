- **Before closing a section, check the change against the rules this plan’s own section 4 shipped.** Section 4 landed five prose lessons into the doctrine, two reviewer charters, the peer-sessions protocol, finishing-work, executing-work, and the docs-curator charter, and the sections after it have already violated two of them: an only-sentence (`X is the only Y`) was falsified by a change adding a second member, and a sanitising guard gained a second producer without moving to the shared boundary as an exported helper. The two with teeth on this plan’s remaining work are exactly those: hunt `only`, `sole`, `single`, and `unique` across any document the change touches and re-read every hit whose sentence asserts a superlative; and where a change gives an existing sanitising or clamping guard a second producer, move the guard to the shared boundary rather than hand-copying its rules.

- **A counted or superlative claim is hunted across the contract the change joins, not only across the files the change edits.** Third recurrence of the counted-claim class on this plan, and the first two entries did not catch it, which is what makes it the workflow’s defect rather than the section’s. Section 5’s implementer ran the superlative hunt faithfully over the one production file it edited and reported it clean, and it was clean; two live sentences elsewhere were falsified by the same change, in `plugins/claude-kit/scripts/kit-statusline.js` and in `docs/security-model.md`, both counting "the modification times of the two files that line was rendered from" for a line the change had just given more inputs. A file the diff never opened is exactly where this class hides, because the falsifying edit and the falsified sentence sit on opposite sides of a contract. So the hunt’s scope is the contract rather than the diff: for every value the change adds an input to, and every set it adds a member to, grep the repository for a sentence counting that set or calling it the only one, and re-read every hit. A cache key is one of these by construction, being a claim about exactly what a value depends on, so a change that widens what a cached value reads has narrowed that key whether or not it touched the file the key lives in.
