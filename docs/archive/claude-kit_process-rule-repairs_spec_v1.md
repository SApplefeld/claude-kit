# Process-rule repairs: amendments reach every path, wedges get a liveness predicate, outlines before whole files, absence checks earn their silence

Status: Complete
Commit Model: Commit-and-Push
Created: 2026-08-22

## Goal

Five process rules in the kit's skills and doctrine have observed gaps: two captured as kaizen notes from the shared-tier authoring run, one adopted from the Warden-AI evaluation (candidate 1, decided 2026-08-22), one adopted from the Unlazy evaluation (decided 2026-08-23), and one surfaced 2026-08-23 by section 2's own review round. When this plan is done: a plan doc's Standing Brief Amendments block binds every execution path including the one that takes no dispatch; a dispatch that wedges silently (running forever, writing nothing) has a defined detection and exit instead of an indefinite stall; sessions everywhere open large files through a cheap outline instead of reading thousands of lines to find one function; an absence-proving check that leans on a hand-authored pattern, path, or scope, not only a test, needs a positive control before its silence is trusted; and the doctrine's two liveness bullets stop overreaching now that a silent wedge has a definition.

## Standing Brief Amendments

Amendments bind every section opened after they are written, dispatched or inline, per `executing-work` step 1. Each names the finding class that earned it.

1. **Never write an unqualified absolute into a rule that other surfaces defer to.** Section 2 produced this class twice in four review rounds: a compensation notch stated without the class it excludes (round 1), and "Only that unanswered window authorizes a TaskStop" stated in the rule that now owns TaskStop authorization, which read as forbidding the three deliberate non-wedge kills the kit requires elsewhere (round 4, raised independently by both reviewers). The failure is not carelessness about exceptions: it is that a rule strong enough to be worth writing is strong enough to be obeyed past the case it was aimed at, and the bold lead is the sentence that survives a skim and a compaction summary. So write the scope into the claim itself ("nothing short of the whole hallmark authorizes killing a dispatch **for being quiet**") rather than annotating it with an exemption afterwards, which `writing-skills` rules does not scope. Before closing any section, re-read each sentence it added that begins with Only, Never, Always, or Every, and check it against the surfaces that state the same verb.

2. **A negation carries an absolute's force and passes Amendment 1's keyword check clean.** Section 3's bold lead was "Open a large file through an outline, not from the top", which begins with none of Only, Never, Always, or Every and was still an unqualified absolute in the always-on layer, colliding with two committed read-in-full mandates elsewhere in the tree. Both reviewers returned it as a Critical. So read Amendment 1's keyword list as instances of the class rather than the class itself: what makes a sentence an unscoped absolute is that it states a rule with no observable condition on it, whatever word it opens with, and a "not X" construction is exactly the form that evades a keyword scan. The repair is the one Amendment 1 already names, and it is worth restating because this section proved the first attempt does not come naturally: fix the predicate rather than annotate the claim. Section 3's real condition was never the file's size, it was that you are hunting for one thing inside it, and once the predicate was corrected both collisions vanished with no exemption clause written at all.

### 2. A liveness predicate for the silently wedged dispatch

Model: opus
Locus: inline

Amend the unavailability rule so its trigger covers the failure mode that produces silence. In `finishing-work/SKILL.md` (the owner, :14): unavailability is confirmed from an actual dispatch failure, or from a pair of wedges at the model in question, neither of which ever wrote a byte, the second being a re-dispatch that separates a transient environment fault from an allotment that is gone. The wedge itself is a dispatch whose status reads `running`, whose transcript has stayed flat across its class's growth window (or that window has elapsed since dispatch with no usable growth reading), and which has not answered a probe across its class's probe window. The probe is the discriminating observation and the other two bound it (revised in execution 2026-08-23 on the consultant's ruling that transcript growth and the probe are not independent observations, a probe answer being itself a transcript append: growth is a one-way short-circuit proving life, plus a cause signal separating never-wrote from wrote-then-stopped, and a zero corroborates nothing). Only the whole hallmark authorizes stopping a dispatch for being quiet, and then the round takes the compensated route exactly as an error-confirmed unavailability does. The recording rule at :20 extends to name which trigger fired, error or hallmark. Update the restatement sites to match: `consult/SKILL.md:37` and `executing-work/SKILL.md:172` and `:203` currently restate the error-only trigger verbatim; reduce each to a pointer at the owner where the surrounding sentence allows, or update the trigger phrase to "a dispatch failure, or the liveness hallmark finishing-work defines" where a pointer alone would leave the sentence unreadable. Check `docs/architecture.md:21` for contradiction (its "two states" sentence describes the compensation, not the trigger; touch it only if it now reads false).

Acceptance: finishing-work states both triggers, the hallmark in its general form with the probe as the discriminator, the growth reading's role and its positive control, the per-class window rule with the review-class numbers, and the extended recording rule; the model a dispatch ran at is read from the dispatch record rather than from the transcript sidecar, whose `model` key is present only where an override was passed; no surface still states the error-only trigger as the whole rule (grep `actual dispatch failure` and read each hit); the single-owner discipline holds (restatements reduced to pointers or updated in the same round).

References: the outline patterns. The 2026-08-22 set was corrected 2026-08-23 after this section's review round ran it against the corpus it cited and falsified three of its four families; each corrected form below was re-run against a real file before landing, and they ship in the style skills rather than in the doctrine. C# regions: `^\s*#region`, the label being the rest of the line (20 hits on the 4,347-line `ApiClient.cs`). C# types: `^\s*((public|private|protected|internal|sealed|static|abstract|partial|readonly|file)\s+)*(class|interface|record|struct|enum)\s+\w`. C# members: `^\s*(public|private|protected|internal)\b.*\(`, excluding lines containing `= ` before the paren and lines containing `{ get` (202 raw, 186 after the filter). Two corrections here. The dash-rule alternative was dropped, being comment decoration in this style rather than section structure, and the banner grep is taken second, its hits outside the definitions' ranges read past rather than scoped away, since the range-restricting forms renumber their output and the line numbers are the point; run whole it returns 6,710 output lines on the 70,966-line vendor install script where the definitions grep alone returns 820. `GO` was dropped outright: 936 structureless hits on that one file. ### 5. The doctrine stops claiming a dispatch with no notification is alive

Model: opus
Locus: inline

Surfaced by section 2's review round and appended 2026-08-23 as approval drift. Repoint standing-watch's line in the same round, writing the hallmark check into the tick order rather than triggering it, since a watch re-blocks on nothing. The bullets' operative instructions, TaskStop the agent before dispatching its successor and probe before you kill, both survive unchanged and stay the point of their bullets. The edit lands byte-identically in both doctrine copies in one round, under the same parity pin sections 3 and 4 carry.

Acceptance: both doctrine copies carry both qualifications identically and `node --test test/doctrine-parity.test.js` passes; no surface still states the unqualified absolute (grep `means a dispatched agent is alive` across the whole tree, the repository root included, run against a state known to contain the pattern first, and read each hit); the probe bullet points at finishing-work's windows rather than restating them, by a route that resolves; `standing-watch:69` no longer claims the doctrine owns the kill rule; both operative instructions survive; a parity-test pin holds each bullet to naming finishing-work, since the bullets defer their whole content there and a symmetric deletion would otherwise pass the whole-body identity check; the output style is untouched (the bullets are outside the register core).
