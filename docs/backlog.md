# Backlog

The living handoff and next-steps doc for the kit. It carries active items only. When an item is done, it moves out to a dated snapshot in `archive/` (`backlog-YYYY-QN.md`) rather than being struck through in place, so this file stays lean and readable.

Per-plan history does not live here. A plan's Chapters are its own append-only record and travel with the plan into `archive/` when it closes. This file is for cross-effort next-steps that do not belong to any single open plan.

The archive index's unbounded growth is the related pressure on the same surface: `recall` caps its read at 64 KB and says so when the cap binds, which converts that growth into a bounded read rather than a bounded digest, so a clip note is the signal to trim the index by hand.

- **Explore channels for unattended interactive runs (research preview).** A channel is an MCP server that injects external events into the interactive session as model input (code.claude.com/docs/en/channels-reference). Two uses for long runs, both keeping the work on subscription billing: a local webhook or scheduler nudging an overnight run's next turn, and permission relay (v2.1.81+) answering tool-approval prompts from a phone. - **Destinations compacted before 2026-07-18 may be truncated, and the reaping advice cannot see it.** Emission reproduced the source's parallel-tool branch topology until the turn-segmentation effort linearized it, so any destination the engine produced from a transcript containing parallel tool calls dropped the losing branch and everything downstream of it, silently: the CLI printed success and the file was well-formed. Measured on the real 884-row `12d49445` transcript, the pre-fix engine wrote 1,074 rows of which 53 were on the active chain. The engine is fixed and `assertSingleParentChain` now fails such a run loudly, but two residues remain. Compacted sessions still in use from before the fix carry only what survived, and their `[UNCOMPACTED]` sources are the only recovery. compact-session's Housekeeping now names this case and gives the detecting check (compare the destination's active-chain length against its source's), so the guidance no longer sends an operator to delete the only recovery copy. The remaining work is the audit itself: for each compacted session still in use from before the fix, compare its row count against its `[UNCOMPACTED]` source, and keep the source wherever the destination holds a small fraction of it. There is no automated sweep for this.
- **Push-time stranded-branch guard (candidate, 2026-07-17).** When a repo auto-deletes merged head branches, a late push to a just-merged branch silently recreates it off the integration line (the stranded-commit trap), signaled only by `git push` printing `[new branch]` for a branch that should already exist. The kit already ships merge-strand-guard and branch-hygiene, and the manual strand-check caught a live instance on the neo project, so this is defense-in-depth, not a gap. A mechanical guard would flag an unexpected `[new branch]` on push. Build only if the trap recurs despite the existing guards; the strand-check working is why it is parked, not prioritized.
- **A written access model for the guard hooks (2026-07-24).** The kit ships four PreToolUse guards (`docs-write-guard`, `pr-docs-guard`, `merged-pr-push-guard`, `readonly-agent-guard`), and each one's policy, accepted risks, and preconditions live only in its own file header. `docs/security-model.md` now exists but covers the memory store alone, and the guard material is split: `docs/architecture.md`'s Hooks section carries the two-class agent policy and the fail-open denylist stance with its tree-comparison backstop, while each guard's accepted risks and preconditions are still only in its own header. What is left is folding the per-guard half into the security model, where it can be re-tested: the compensating controls (the tree-state comparison around a review round, the agents' frontmatter granting no write tools) and the gaps each control cannot see (a `gh` mutation leaves the worktree byte-identical). Surfaced by the security review of the readonly-agent-guard effort, which had to reconstruct all of that from code to do its job.
- **The guard hooks' own executables are writable by the agents they govern (2026-07-25).** The plugin loads from a cache snapshot under `~/.claude/plugins/cache/applefeld/claude-kit/<hash>/`, and a governed agent holding Bash can write there: one overwrite permanently disarms all four PreToolUse guards, on a path outside any git root so no tree-state comparison can observe it. A denylist rule matching the cache path was considered and rejected, because it would stop only the naive spelling of a mutation the fail-open posture deliberately declines to chase (the same write is reachable through `node -e`, a python one-liner, or a variable-assembled path). So the real question is a design fork rather than a regex: should the loader read the guards from a location the agents cannot write, or does the kit accept that a governed agent can disarm its own guard and rely on the agents' lack of motive? Confirmed reachable with a real exit code during the readonly-agent-guard effort's finishing review; parked because the fix is architectural.

- **Whether an armed `/kit-goal` leash survives a native harness compaction is unverified (2026-07-24).** `kit-goal-stop.js:410-427` enforces on session identity, not on the state file existing: the stopping session either matches `boundSession` or is reachable from it through the compaction ledger, and anything else resolves as a bystander whose stop is allowed. Only `compact-cli.ts` writes a ledger row, so a manual compact-session swap is the one swap that rebinds. That leaves two possible behaviors and no evidence deciding between them: if the harness preserves `session_id` across its own compaction the leash holds untouched, and if it mints a new id an armed run is silently unleashed at its first auto-compaction. The corpus cannot answer it, since no native compaction appears in the local kit transcripts or the ai-os corpus and `nativeCompactions` in `tools/transcript-study/analyze.mjs` is printed but never incremented. A cheap probe settles it: arm a goal, drive one session past the native compaction threshold, then compare the successor's session id against the armed `boundSession` in `.kit/goal-state.json`. If the id changes, the leash needs a recognition route that does not depend on the engine's ledger.
