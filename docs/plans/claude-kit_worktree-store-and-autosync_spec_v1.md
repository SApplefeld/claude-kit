# Worktree Store Resolution and Silent Memory Sync

Status: In Progress
Commit Model: Commit-and-Push
Created: 2026-08-19

## Goal

Two defects in the memory store's daily ergonomics, both operator-reported 2026-08-19. First: `memq` resolves its store from the working directory alone, so a git worktree of a checkout resolves a different, empty store (`D--EleosCore-tforce` instead of `D--EleosCore`), silently, while the kit itself encourages worktrees. A worktree resolves its main checkout's store. Second: the SessionStart sync nudge fires every session while memories pile up uncommitted, and the only sanctioned sync path is a consented doctor `-Fix` plus a manual pull/push. The store syncs itself silently: when the store root is the doctor's own repo and every leak probe reads clean, the kit commits through the same allowlist gate and pushes where an upstream exists; a store with no remote commits locally and says nothing, because the missing remote is deliberate (the operator's standing instruction, this session, plus the operator-tier memory `memory-store-syncs-from-this-machine`: one VM's store must never gain a remote).

## Approach

**Section 1 mechanism.** The fix lives in one function: `projectSegment` (`plugins/claude-kit/scripts/memq.js:398`), because the SessionStart hook consumes memq as a module (`memory-session.js` calls `memq.projectMemoryDir(cwd)`), so memq CLI and the hook's write-destination block move together with no second resolver to drift. When no pin is honored and `<cwd>/.git` is a regular file, parse its `gitdir: <path>` line; when the resolved path ends in `.git/worktrees/<name>` AND the two-way handshake holds (the file `<gitdir>/gitdir` resolves back to exactly `<cwd>/.git`), sanitize the main checkout root instead of cwd. The handshake is the security boundary: a `.git` pointer file is on-disk data in a directory the session cd'd into, the same trust class as the committed env files the `KIT_MEMORY_PROJECT` gate exists for (memq.js:329-336), so a planted pointer alone must never redirect memory reads and writes; only a link git itself maintains has the back-pointer. A worktree-shaped `.git` file that fails the handshake falls back to the cwd derivation with a once-per-process stderr note (operator-approved this session), because a silently split store is the defect this section fixes. Submodules are excluded by construction (their gitdir targets `.git/modules/`), the pin keeps precedence, and only `<cwd>/.git` is consulted, never an upward walk (parity with today's subdirectory behavior).

**Section 2 mechanism.** A new `plugins/claude-kit/doctor/sync-store.ps1` (Windows PowerShell 5.1, like the rest of the doctor; `pwsh` is absent on SCOTT-CLAUDE per the operator tier) dot-sources `install-memory-sync.ps1` and reuses its probe and commit machinery unchanged: `Get-MemorySyncStatus` decides, `Install-MemorySyncRepo` commits. It mutates nothing unless the store is the doctor's own repo (ownership config key), both managed files read Canonical, all four leak probes ran and answered clean, and HEAD is not detached — the doctor's PASS bar, re-derived per run, never cached. When clean: commit pending memory-tier changes (the installer's own pre/post index gates still guard the add), then, only when an upstream is configured, `git pull --rebase --autostash` (abort the rebase on conflict) and `git push --quiet`. No upstream means commit-only and silence, by design. The script is single-flight (a lock file with staleness), always exits 0, prints nothing, and records its outcome to `<storeRoot>/kit-sync-state.json` (ignored by the exclude-all allowlist, so it can never be staged) as fixed enum codes, never free text.

The SessionStart hook's `syncNudge` becomes the sync trigger. Same detection (own `.git` directory, ahead/behind counts, porcelain dirty), with one widening: a dirty store with no upstream now counts as pending (today it returns null before the dirty check), because commit-only stores deserve commits too. When pending: read the state file; a recorded gate-class failure emits the loud doctor line (a broken allowlist is the one state where nagging is correct); a transient failure streak older than 7 days (`firstFailSince` in the state file) emits one soft line; otherwise spawn the sync script detached and emit nothing. The hook's no-store-derived-text discipline holds: state-file reason codes map to fixed literals in the hook, unknown codes to a generic literal, and no path, branch, or git output ever rides the line. No spawn under an external-engine/run-scoped session (a fleet of workers each spawning sync is contention with no owner) or where powershell.exe is unavailable, which falls back to the current nudge text.

**Why not loosen `KIT_MEMORY_PROJECT` for section 1:** the pin is honored only alongside the gated store pair by design; an innocuous env var settable from a repo's committed files must not move an attended session's memories (memq.js:329-336). The worktree handshake reaches only "the main checkout of the same repo," which is the wanted semantics; the pin reaches anywhere.

**Why the trigger is SessionStart only:** it is where the nag fires today and where staleness is observed; a Stop-hook trigger would fire every turn for a store that syncs at most once a session boundary. Memories written this session sync at the next session start.

**Execution constraints.** Sections 1 and 2 touch disjoint files but share the machine's one test-run budget and the build stamp: run them sequentially, 1 then 2. Any edit under `plugins/claude-kit/hooks/` requires `build.ps1` before trusting `hook-canary.test.js` (operator-tier memory `claude-kit-hook-edits-need-a-build-stamp-refresh`); check whether `scripts/memq.js` and `doctor/*.ps1` are in the stamped manifest and rebuild regardless after each section. Suite invocation is `node --test test/*.test.js` (bare directory form dies on Node 24); the baseline is not zero-fail (memq-shim carries 2-3 environment-driven failures, one intermittent) — capture the real baseline before section 1 and diff every gate against it. NTFS collapses case-variant fixtures into one file: no worktree test fixtures that differ only by case.

## Sections of Work

### 1. Worktree store resolution in memq
Model: opus
Files in scope: `plugins/claude-kit/scripts/memq.js`, `test/memq.test.js`.

A resolver in memq.js: given a cwd, when `<cwd>/.git` is a regular file whose FIRST line is `gitdir: <path>` (relative resolved against cwd) naming a path ending `.git/worktrees/<name>`, and the full handshake closes, `projectSegment` sanitizes the main checkout root instead of cwd; pin precedence unchanged, memoized per cwd. The handshake, cheap-first: on win32 a UNC/device-rooted gitdir whose root is not cwd's own is rejected on the path text before any filesystem op at the target (opening a UNC path is an auto-authenticating SMB connect, so the read is the exploit); the resolved gitdir is capped at 2048 chars; `<main>/.git` must be a directory; `<gitdir>/commondir` must be a regular file; and `<gitdir>/gitdir` must resolve back to exactly `<cwd>/.git` (fsEq, case-insensitive on win32). Pointer reads are bounded (4 KB) and fstat-verified on the open descriptor (O_NONBLOCK off win32, closing FIFO-block and TOCTOU together). An accepted main root folds through `fs.realpathSync.native` on win32 only (case-preserving segments beside case-folding comparisons would otherwise mint a third store; POSIX keeps the lexical value so a symlinked checkout keeps its chosen identity). Two once-per-process stderr notes, fixed literals: a worktree-shaped pointer whose handshake fails (naming `git worktree repair`), and a successful resolution when the worktree's own path-derived store also exists on disk (its records are no longer read). Pre-handshake rejections (submodule shape, non-pointer content, UNC, over-cap) stay silent; bare-repo worktrees (`<repo>.git/worktrees`) deliberately keep their own stores, since a bare repo has no main working tree whose store they should share.

Tests (a floor, extend as implementation reveals): synthesized fixtures in a temp root (no git dependency), under the gated `KIT_MEMORY_ROOT` pair the existing memq tests use — (a) valid worktree handshake resolves the main checkout's segment, and `projectMemoryDir` from the worktree cwd equals the main checkout's dir; (b) missing back-pointer file falls back to the cwd segment and writes the stderr note once across two calls; (c) back-pointer naming a different worktree's `.git` falls back; (d) submodule-shaped gitdir (`.git/modules/x`) falls back with no note; (e) `.git` as a directory keeps today's behavior; (f) an honored pin beats a valid worktree; (g) relative `gitdir:` path form resolves; (h) the memoization returns consistent answers on repeated calls.

Acceptance: all tests green; full suite delta against the captured baseline is zero new failures; from a real `git worktree add` checkout of this repo (manual verification in-session, then removed), `memq recall` reports the main checkout's project tier.

### 2. Silent store auto-sync
Model: fable
Files in scope: `plugins/claude-kit/doctor/sync-store.ps1` (new), `plugins/claude-kit/hooks/memory-session.js`, `test/memory-sync.test.js`, `test/memory-session.test.js`.

The sync script and the hook trigger, per the Approach. Script contract: mandatory `-StoreRoot` (mirrors the installer's no-default discipline; the real root holds credentials), exit 0 always, no stdout/stderr on any path, single-flight via `<storeRoot>/kit-sync.lock` (created exclusively, removed on exit, treated as stale past 15 minutes), state recorded to `<storeRoot>/kit-sync-state.json` with fields `lastAttempt` (ISO), `lastResult` (`ok`|`gate`|`transient`), `reason` (fixed enum: `leaks`, `foreign`, `drift`, `unproven`, `detached`, `commit-failed`, `pull-conflict`, `push-failed`, `lock`, `git-missing`), `lastOk` (ISO), `firstFailSince` (ISO, set on first failure after a success, cleared on success). Gate classes (`leaks`, `foreign`, `drift`, `unproven`, `detached`) mutate nothing at all. Git runs through `Invoke-MemorySyncGit` argv arrays only; push and pull take no URL or refspec arguments (configured upstream only); a failed rebase is aborted before exit.

Hook contract: replace `syncNudge`'s single sentence with the trigger logic in the Approach, keeping its existing hard rules — the store root's own `.git` directory required before any git call, the literal `@{upstream}` token, integers-and-fixed-literals only in emitted text. Spawn shape: detached, stdio ignored, unref'd, `powershell.exe -NoProfile -ExecutionPolicy Bypass -File <script> -StoreRoot <root>`, script path resolved from the hook's own directory (`__dirname/../doctor/sync-store.ps1`), never from an environment variable. No spawn when the session is run-scoped/external-engine (the hook already computes this state) — the current nudge stays for that path too, silenced as it is today.

Tests (a floor): script-level in `test/memory-sync.test.js` style (powershell.exe spawns, Windows-only skip guard), against temp store roots — (a) canonical own repo, dirty memory tier, no remote: commit lands, state `ok`, nothing printed; (b) with a local bare repo as origin and upstream configured, ahead: push lands on the bare repo; (c) behind the bare origin: pull rebases and both sides converge; (d) a tracked disallowed path: state `gate`/`leaks`, no commit, no push, index untouched; (e) foreign repo (no ownership key): state `gate`/`foreign`, nothing written; (f) divergent histories that conflict: rebase aborted, state `transient`/`pull-conflict`, worktree clean; (g) lock file present and fresh: exits without touching git, lock not deleted. Hook-level in `test/memory-session.test.js`: (h) pending + no state file emits no sync text and the state file appears (poll with timeout; Windows-only); (i) state `gate` emits the doctor line; (j) `firstFailSince` older than 7 days emits the soft line, exactly one; (k) clean store emits nothing and spawns nothing (no state file appears); (l) no-upstream dirty store gets a commit (spawn happens). Existing syncNudge tests are updated to the new contract, never deleted without replacement.

Acceptance: all new tests green; full suite delta against baseline zero new failures; `build.ps1` run after the hook edit and `hook-canary.test.js` green; a real run against this machine's live store (which is currently dirty and 2 ahead) commits through the gate and pushes, verified by `git -C ~/.claude log` and `status` — this is the operator's own acceptance case.

Raised as a decision ask at close-out.
- A POSIX sync runner. The hook falls back to the current nudge where powershell.exe is absent; the `doctor.sh` backlog item (2026-07-09) is where a POSIX sibling belongs.
- Auto-resolving jsonl merge conflicts across machines. A conflicted rebase aborts to `transient` and surfaces after 7 days; union-merge strategies are future work if the streak nudge ever fires in practice.
- Loosening the `KIT_MEMORY_PROJECT` gate. Argued in the Approach.
