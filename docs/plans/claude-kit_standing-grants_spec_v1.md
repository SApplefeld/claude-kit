## Goal

The kit gives the operator no durable way to hold a standing operational grant, so every grant decays to a per-session one and every new seat re-asks. The NEO-CLAUDE seat's live instance: the operator granted store-push authority on 2026-08-29, the grant sits in the operator tier in the operator's own words (`memory-store-pushes-need-no-permission`), and the seat still re-asked twice in one day, correctly, because the coordinator runbook says the seat "runs no git in the store", its board-write rule says "no staging, no commit, no push", both unconditional, and the only durable authorization the doctrine names is a plan header, which a store is not. The structural reading is right in effect and wrong in one particular: the kit already ships the needed shape. The role skill's standing-delegation model is a working standing-grant rail, the skill body defining the model's scope and exclusions while an operator-tier record is only the on-switch, the record's body data that can neither widen nor narrow, the ceiling stated as provenance rather than credential. This plan generalizes that rail, names the store's sanctioned sync path as its second instance, and gives the flat prohibitions their carve-out, so a grant the operator has already given stops being re-asked.

Two principles, binding on every section:

1. **The record is only ever a switch.** A standing-grant record turns on a mechanism whose entire scope, exclusions, and procedure a shipped skill states; the record's body is data. What the rail can never reach, stated as the rail's own exclusion list: it extends no warranted channel (the coordinator skill's closed list of three stands), it establishes no privacy precondition (the role skill's Workdir readership bar stands verbatim, deliberately record-proof), it lifts no harness floor and no no-laundering rule, and it widens no grant past what its owning skill spells out. A countersignature clause was considered and rejected: a countersignature is more text in a record any local session can write, so it adds nothing a dishonest writer could not also type, while the rail's security property, scope living in the operator-controlled repo rather than in the record, needs no signature to hold.
2. **The first generalized instance must be blast-radius-neutral.** The store-push grant switches on nothing this machine does not already do unattended: the memory-system SessionStart hook spawns the store sync in the background on Windows, and that sync commits and pushes through the allowlist gate on its own. The grant only lets a seat invoke the same sanctioned path (the sync script itself, `plugins/claude-kit/doctor/sync-store.ps1` with an explicit `-StoreRoot`, never a bare `git add`, which bypasses the allowlist leak probes) at moments of its own choosing.

## Standing Brief Amendments

Binding on every section opened after the entry's date, dispatched or inline. Section 1's review round earned the first.

1. **(2026-08-31, from section 1's security re-review.) A pin over a bounded list pins the sentence that scopes the list, not only its items.** Section 1 shipped a pin asserting the four bars of the standing-grant rail's exclusion list and left unpinned the lead-in that says whose list it is. Rewriting that one sentence from "What the rail can never reach" to "What the delegation model can never reach" would have narrowed a boundary binding every future grant down to a single instance, with all four pinned phrases still present and the suite still green. So any pin this plan adds over a list, a closed set, or a rule stated as binding on a class asserts three things and not one: the items, the sentence scoping them to the class, and the sentence declaring the set closed where one exists. The general form, which is what carries past this plan: a screen that asserts a list's contents and not its quantifier is defeated by editing the quantifier, and that edit leaves every asserted string in place.

2. **(2026-08-31, from section 1's security re-review.) A control proves reach only when the mutation it runs leaves the text present and grammatical.** Deleting a string the predicate was handed proves the instrument executes and says nothing about what the predicate would catch. Every pin this plan adds is accompanied by a control that mutates the target the way a later editor plausibly would, a re-scoping, a softened qualifier, a narrowed quantifier, and shows the predicate going red on that. Run the control from the `.kit/` scratch path against an in-memory copy so the tree under review is never mutated.

3. **(2026-08-31, from section 1's blind and adversarial rounds converging.) Assert nothing about a sibling section's not-yet-landed content.** Section 1's first draft stated as present fact what the coordinator skill would say after section 2 lands, and that skill says none of it; under this plan's Commit-and-Push model the untrue sentence would have reached origin. Where a section must refer to a contract another section will write, it assigns ownership ("X is that skill's to state") and fails closed on the assignment being unmet, rather than describing the content.
4. **(2026-08-31, from section 2's third review round and the consult that ruled on it.) Measure a grant's blast radius against what the same actor can already do, never against the strongest existing caller of the same mechanism.** Section 2's second round bounded the store-push grant by asserting the seat's hand run was equivalent to the SessionStart hook's unattended spawn of the same script. That equivalence is false at the code: the hook builds a child environment stripping every `GIT_*` variable (`plugins/claude-kit/hooks/kit-git-lib.js:59-72`), the PowerShell scripts perform no such scrub of their own, and the hook's ownership gate is the unclonable `--local` config key where the script's own test accepts a marker-bearing `.gitignore` first. No prose can make a hand run inherit a guard the script does not perform, so the claim was unfixable as written. The correct baseline is what a session can already do by hand into the same store, which two shipped skills document as bare git. The general form, which is what carries past this plan: a neutrality claim names the baseline it is measured against, and that baseline is the actor's existing reach rather than the best-guarded caller of the mechanism, since comparing against the best-guarded caller states an equivalence the actor's own path cannot deliver.
