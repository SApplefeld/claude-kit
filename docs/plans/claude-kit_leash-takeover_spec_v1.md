## Intent

The frame, in the operator's words of 2026-09-16 on the coordinator's relay thread: "On the kit gap, yes, let's write a spec to fix that. We can tackle it behind the memory one," and then "That sounds great. Please proceed." The gap is the one the coordinator found that morning: a supervised persona relaunched after its leashed session died read the leash as another session's business and idled for over four hours until the operator relayed a takeover by hand.

**What done needs.** A relaunched session learns at session start whether the leash's holder is alive or has gone silent past a bound, on an instrument that errs in neither direction, and where the holder is silent it is handed the one command that takes the leash over. That command refuses while the holder shows a turn record inside the bound and proceeds when it shows none, continuing the queue as it stands and recording the takeover with its evidence.

**What done does not need.** An automatic bind at session start, because the kit says and does not do. A liveness file a supervisor writes, or an environment variable for the bound, because the transcript instrument proved sufficient and either would add a second source of truth. Any change to the Stop hook, the compaction gate or the other readers of the binding, because they compare the one field the takeover rewrites and answer correctly for the new holder at their next read.

**Alternatives refused.** The transcript file's modification time as the instrument, refused because it is touched by things that are not turns and read a session as alive whose last turn was ten hours old. The turn-end heartbeat in the operator tier, refused because it lags by the whole length of the turn it is inside and read a working session as dead. A takeover that remakes the arming, refused because it would retire an operator-typed queue's parallelization request mid-queue.

## Goal

When this is done, a session that starts in a project whose kit-goal leash is bound to another session reads, at session start, whether that holder is still working or has gone silent past a bound, and where it has gone silent the notice prints the one command that takes the leash over. That command, a takeover form of the arm, refuses while the holder shows a turn record inside the bound and proceeds when it shows none, rebinding the queue as it stands to the session that ran it and recording the takeover in the goal state's history with the evidence it read. A leash is therefore never taken from a session that is working, and never left stranded on one that has died or frozen for longer than the time it takes to notice. It matters because today a supervised persona relaunched after its leashed session died reads the leash as another session's business and idles until the operator notices the silence and relays a takeover by hand, which on 2026-09-16 cost the dev worker over four hours, and because sessions that freeze on a model or usage limit show a live process and a dead transcript, which is exactly the case this rule reads.

## Approach

**What exists, read from the code at 5e51f266.** The goal state at `.kit/goal-state.json` carries `boundSession` and `boundTranscript` as a pair, written by `armGoal` (`plugins/claude-kit/hooks/kit-goal-lib.js:1884`) when the arming session's id is corroborated by a transcript on disk under the harness's projects tree (`~/.claude/projects/<project>/<session-id>.jsonl`), and `armingSession` beside them as the claim route for an unbound arm. `sessionHoldsLeash` (`kit-goal-lib.js:235`) answers who holds it: the bound session where one is bound, else the arming session. Since the leash status truth plan landed on 2026-09-23, `normalizeState` (`kit-goal-lib.js:257`) repairs the binding on every read through `isBindableSessionId` (`kit-goal-lib.js:2342`), the predicate `bindSession` itself enforces, so a stored `boundSession` the bind function would refuse reads back as no binding. The takeover reads the state after that repair, so a binding that fails the predicate is the unbound case, which the takeover refuses and the notice's unbound voice already covers; a dead holder whose transcript still exists passes the predicate and stays bound, which is the case this plan reads. The session-start hook composes the armed-goal notice in `composeGoalBlock` (`plugins/claude-kit/hooks/session-start.js:476`) in three voices: bound to this session, bound to another session, and bound with no session id in the payload. Since the same plan landed, the notice names every queued plan path up to the line bound the goal command uses and counts only the rest, and the fourth voice this plan adds carries that queue clause exactly as the second does. The second voice carries a liveness hint from `lastActivePhrase` (`kit-goal-lib.js:2489`), which reads the bound transcript's file modification time and renders it as "about N minutes ago", and it tells the session the plan is not its business and that a typed `/kit-goal <plan paths>` re-arms it. The CLI's `status` verb renders the same phrase. A re-arm is already a clean rebind: `armGoal` binds to whoever runs it, and the kit-goal skill names a typed `/kit-goal` as the operator's re-arm and `arm --self-armed` as a run's own, drawing its authority from the plan's committed `## Dispatch Authorization`. The Stop hook and the compaction gate both test the leash through `sessionHoldsLeash`, so a session that loses the leash while it is still running is released at its next stop rather than held.

**Why the transcript's newest turn record is the instrument, and not the file's modification time.** The kit memory store's operator tier, the shared tier every project on this machine reads, records two measurements. A heartbeat a session stamps at turn end lags by the whole length of the turn it is inside, six hours in one measured case, so it errs toward dead. A transcript file's modification time is touched by things that are not turns, fifty four minutes old on a session whose last turn was over ten hours old, so it errs toward alive. The timestamp of the newest turn record inside the transcript was accurate in both directions on every session measured. Two transcripts from 2026-09-16 on this machine fix the bound. The dev session killed that morning ran four hours of kill-performing suites and its longest silence between records was exactly ten minutes, fourteen times, each a bounded wait on a background run, because every tool call the harness runs is capped at ten minutes and the harness writes a record at each tool result. The relaunched session's one longer silence was its idle stretch with no leash and nothing to do. So a leashed session running a turn writes a record at least every ten minutes, and one silent past that in its own turns is frozen or dead. The bound is fifteen minutes: the cap plus margin. One case sits outside that reasoning and the instrument reads it. The Stop hook's clause (c) lets a leashed holder end its turn on a leading `WAITING:` line while a background dispatch runs, and the holder then writes no record of its own until the dispatch completes and re-invokes it, which for a reviewer or an implementer can exceed the bound. A running dispatch writes to its own agent transcript under the holder's session directory, so the instrument reads the newest turn record across the holder's own transcript and every subagent transcript beneath it, and a holder awaiting a long dispatch reads as alive on that evidence rather than as silent.

**The takeover is a form of the arm, and it binds nothing on its own at session start.** `arm --takeover` reads the goal state, refuses when nothing is armed or the goal is unbound, refuses when the bound session is the caller's own, reads the holder's silence across its own transcript and its subagent transcripts, refuses with the age it read when the newest record is inside the bound, and otherwise rebinds the queue as it stands to the caller. The fields it rewrites form a closed set: `boundSession` and `boundTranscript` to the caller's pair, `armingSession` to the caller's id, and `armedAt` to now. Every other field the state holds, `plan`, `queue`, `queueIndex`, `armedBy`, `condition`, `authorizations`, `history`, `blockedAdvance` and any field a later version adds, is carried over byte for byte, so the position is kept and the per-plan arming is not remade. Carrying `armedBy` over is deliberate: it is what each plan was armed under, and an operator-typed arming carries that run's parallelization request, so a takeover that rewrote it to `self` would retire that request mid-queue. The takeover continues the arming rather than making a new one. It refuses, naming the cause, when the caller has no corroborated session id, that is, when the arm would bind to nobody, since a takeover that leaves the leash unbound is the stranding this plan exists to end. It appends one entry to `history` of the form `{ kind: 'takeover', from: <old boundSession>, to: <new boundSession>, at: <ISO>, silentFor: <seconds>, instrument: <'own-transcript' | 'subagent-transcript'> }`, the instrument naming which stream carried the newest record it read. `takeoverGoal(cwd, bind, authority, expected)` takes the caller's snapshot `expected: { plan, armedAt, boundSession }` and refuses when the re-read state no longer matches it, the same compare-and-swap `advanceGoal` carries (`kit-goal-lib.js:2256`) with `boundSession` added, so the CLI reads the state once, derives the silence from it, and passes that read back as the snapshot; two relaunched sessions racing for one leash then produce one holder and one refusal naming the swap. It takes `--self-armed` under the skill's existing flag rule: a session running the takeover on the notice is the run's own invocation and carries the flag, an operator typing it omits the flag, so the notice prints the flagged form. The flag records who ran the takeover, in the history entry and in `armingSession`, and does not touch `armedBy`, so it never retires the queue's arming. The session-start notice gains a fourth voice for a bound session whose newest turn record is older than the bound: it says the holder has been silent for that long, names the instrument, and prints the exact takeover command. It never runs the command. The takeover draws its authority from the taken-over plan's committed `## Dispatch Authorization`, exactly as `arm --self-armed` does under the kit-goal skill, and never from any silence in the doctrine's list; a primed worker is the party that decides to act on the notice, so the kit says and does not do. The fourth voice replaces the second only when the bound is crossed; inside the bound the second voice stands as it is, with its liveness hint rekeyed to the same instrument so the two voices cannot answer one transcript differently.

**The bound is one constant.** `LEASH_SILENCE_BOUND_MS` in `kit-goal-lib.js`, fifteen minutes, read by the takeover and by the notice through one exported function, `holderSilence(state)`, which returns `{ silentForMs, instrument, transcript }` for the newest reading across the bound session's own transcript and its subagent transcripts, or `null` where no transcript can be read. No configuration file and no environment variable overrides it: a second source for the bound would be a second source of truth, and no requirement names one. A machine that needs another bound changes the constant.

**The transcript instrument governs the leash's liveness question, and the peer-sessions skill says so.** That skill's Liveness paragraph today ranks a `ListAgents` busy or idle reading above a transcript-mtime hint and sends a re-arm over a live-roster session to the coordinator or the operator. The takeover keeps the second half and replaces the first: the instrument is the transcript's newest turn record, not its mtime, and a holder past the bound is taken over on that reading even where a process for it still appears on the roster, because a session frozen on a model or usage limit is exactly a live process with a dead transcript. A holder inside the bound is left alone, and a re-arm over one still goes to the coordinator or the operator as that paragraph says. Section 3 amends the paragraph to state this, and the operator's approval of this plan is what ratifies the ranking.

**What the instrument reads and what it cannot.** `holderSilence` reads the last 256 KiB of the bound session's own transcript and of each transcript under the session directory's `subagents/` tree, its workflow subagents included, and takes the newest `timestamp` on a record whose `type` is `assistant` or `user`, the two record kinds a turn writes, across all of them; `system`, `attachment` and progress records are skipped because the harness writes some of them outside turns, and a subagent transcript whose own newest record is old contributes nothing, so only a running dispatch lifts the reading. A transcript with no such record in its tail, an unreadable transcript, or a newest timestamp more than five minutes ahead of the reader's clock returns `null`, a smaller lead being read as now to absorb clock skew, and both readers treat `null` as inside the bound: a takeover refuses on it, naming the cause, and the notice keeps the second voice. That is the fail-closed direction, because the cost of taking a live session's leash is two sessions in one tree, and the cost of not taking a dead one is the manual re-arm that exists today. The one residual the rule accepts is a frozen session that thaws after its leash moved: its next stop finds it unleashed and lets it end, so it costs at most one turn of edits, and the notice's wording says so to the session that took over.

**The sweep.** Step 7's scout ran on 2026-09-16 over the checkout at 0ea175b6 with the question "every surface that speaks the leash binding contract", and the 2026-09-24 re-anchor re-ran its content search over 5e51f266 and found the same sites with the additions the paragraph above names, searching `plugins/claude-kit/` for readers and writers of `boundSession`, `boundTranscript` and `armingSession` and callers of `sessionHoldsLeash`, `armingSessionClaims`, `bindSession`, `lastActivePhrase` and `armGoal`, the skills, agents and `docs/` for the rule in prose, `test/` for the pins, and `hooks.json` with the build scripts for the registration. The sites that read the leash through `sessionHoldsLeash` and do not change are the Stop hook (`kit-goal-stop.js`), the compaction gate (`kit-compact-gate.js`), the checkpoint CLI and library (`kit-compact-checkpoint.js`, `kit-compact-lib.js`), the deferral and chapter-boundary nudges, and the status line widget: a takeover rewrites `boundSession` through the same field those readers already compare, so each answers correctly for the new holder at its next read with no edit, and a compaction checkpoint the old holder banked reads as another session's and is left in place, which is the behavior `kit-compact-lib.js` already pins for a mismatched session.
