## Dispatch Authorization

The ARCHITECT persona wrote this plan on 2026-10-02 as plan 2 of the operator's memory-in-SQL ask, approved on the ARCHITECT's channel that day ("Love it. Approved all the way down."). It has one precondition, on dispatch: plan 1, `claude-kit_memory-in-sql_spec_v1.md`, has merged, the host runs schema version 7, and the operator has confirmed on the ARCHITECT's channel or the coordinator's that `memq db-sync` on each of SCOTT-CLAUDE, NEO-CLAUDE and ASR-CLAUDE prints its migration marker. ## Goal

When this is done, the kit holds no code that reads or writes a markdown memory tier, syncs the kit's home through git, builds a local search index, or installs an embedding model, and no document that says it does. The session-start hook, the recognition nudge, the usage-stamp hook, every `memq` verb and the judgment sidecar read the database through `memq` or the snapshot it keeps, and nothing else. The doctor's Memory sync and Embedder steps are gone, its Memory database step is the one memory step, and it reports an old tier directory still on disk as information with the one command that removes it. The coordinator directory is no longer synced, its skill says the board, the registry and the admin requests are this machine's own, and of the probe scenarios that staged the file store, two are retired and three re-seeded on the `memq` door and the snapshot. The run-scoped pending directory stays, since the external engine adjudicates it by file. The whole suite is green with the retired tests gone and no cap in `test/size-budget.json` left pointing at a removed file.

## Intent

The frame, in the operator's words of 2026-10-02. "SQL memory is the tool all the way down, excepting the local queue and small cache." On the local index: "I agree. Remove it. Let's move all memory into SQL." On the coordinator directory: "I don't think we need the Coordinator Board to be synced at all. It's a scratch pad for active, current work that the Coordinator was tracking, and it's largely replaced by walking the Goals of each persona ... I think we can stop syncing it entirely. If an interactive session uses the coordinator board, then it can simply keep it locally, it doesn't need to be git backed up." On the whole: "Love it. Approved all the way down."

What done needs to do. Remove the readers and writers of the file tiers, the git sync and its installer, runner, doctor steps and state, the coordinator directory's sync, the local index and the embedder, with their tests and their prose. Retire two probes and re-seed three. Leave the pending directory. State how an operator removes the old files by hand.

What done does not need to do. It does not delete a file on any machine; the doctor names the command and the operator runs it. It does not move the coordinator directory into the database. It does not touch the persona repository, the memory database's schema, or the host. It does not remove `KIT_MEMORY_ROOT`, which from plan 1 on names the root the queue and the snapshot live under, or `KIT_RUN_ID`, which the pending directory still keys on.

Alternatives refused. Keeping the git sync for the coordinator directory alone: refused by the operator, since the directory is a local scratch pad. Keeping the local index as an outage fallback: refused by the operator. Deleting each machine's old tiers from the doctor under `-Fix`: refused here, since a deletion of a thousand records with no other copy than the host is an act the operator runs at the keyboard after reading the migration marker, not one a repair step takes. Keeping the frontmatter guard as a signpost: refused, since from plan 1 the session-start text names `memq put`, and a hook that refuses writes into directories nothing reads is a mechanism with no requirement.

Rulings after the spec shipped: none yet.
