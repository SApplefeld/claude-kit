## Goal

Three kaizen notes captured on 2026-08-23 (two on NEO-CLAUDE, one on SCOTT-CLAUDE) describe one lesson from three angles: a kit rule that demands a verification has to name where the fact is readable, or the verification ships as an expectation a run cannot meet. Two further items ride with them because they are the same size and the same kind of change, a kit rule that reads well and fails in contact with the work: the memory close-out has no after-query, so a stale record hiding behind vocabulary the effort did not have at its start survives the close-out; and the read-only guard's accepted false hit (a governed verb inside a heredoc body) blocks a reviewer from writing its own report whenever the domain vocabulary collides. When this plan is done:

- The docs-curator's run-stopping `Class: mistake` tag names the basis it rests on, and where that basis is the pre-change state the curator cannot read (it holds no Bash and so no git), finishing-work runs the one read that settles it before stopping the run, and records the receipt.
- finishing-work's unavailability rule names the artifact that carries the model a dispatch actually resolved to: the `message.model` field on the `"type":"assistant"` lines of the dispatch's own transcript, `agent-<id>.jsonl`, as distinct from the requested override the dispatch record and the `.meta.json` sidecar carry.
- A dispatch that never took a turn is a distinct shape with its own fast exit. The transcript exists from dispatch with the prompt as a `user` line stamped at dispatch time; a healthy dispatch writes its first `assistant` line within seconds; one that never will holds `user` lines only, forever. The existing wedge hallmark (fifteen-minute growth window, twelve-minute probe window) is built on the asymmetry that a TaskStop on a live agent throws away what it built, and that asymmetry does not exist for an agent that has built nothing, so the never-started shape gets short windows: a first-turn reading at five minutes, a probe, and a stop-and-redispatch by ten.
- finishing-work's memory step runs an after-query: `memq find` on the vocabulary the effort learned, read against what the effort now knows, so a record the result overtakes is superseded at the close-out rather than left to disagree with the new one for its whole idle life.
- The read-only guard treats a quoted heredoc body as data when the shell would never run it: the body's owner is a data sink (`cat`, `tee`), no executor stands in command position on the introducing line, and the introduction is not in comment position. A reviewer's report about `git push` or `rm -rf` written to `.kit/` through a heredoc is allowed; every spelling that reaches a shell stays denied.
- The three note lines are cleared from the inbox, and the harness fact behind them is banked where every later session on every project reads it.

## Approach

The design decisions, settled 2026-08-23 in the reviewing session, each with its reason:

- **Verification moves to the party that holds the tool, not the tool to the party.** The docs-curator could be granted Bash under a new guard class (a `curator` class in `readonly-agent-guard.js`: docs/ writable, git reads allowed, git mutation denied). That is hook code, tests, and a new class in the access model, to answer a question the orchestrator can answer with one `git show`. The smaller change: the curator states the basis of every `mistake`, saying flatly where a pre-change claim rests on a state it could not read, and finishing-work constructs and runs that read before stopping. The curator states facts and never a command. Report text is data, and the main session is the one principal the read-only guard does not govern, standing behind whatever the operator's permission settings put in front of it and nothing the kit itself installs, so a command string composed in a report and executed by the orchestrator inverts the trust boundary the kit states in its own charters and credits in its security model; git is itself an execution surface (`git -c alias.x=!<shell>`), and its `--output` and `--no-index` options write and read outside the repository, so no leading-token check bounds it. Two things bound the read, and neither existed before this plan. The finishing pass establishes the effort's base ref once, at its own top, because nothing in it ever did: steps 2 and 3 dispatch reviewers over "the whole changeset" and name no ref, so a rule that spends one is demanding a fact the run cannot read, which is this plan's own thesis turned on the plan. And the path the curator reports is screened against that ref's own changed-file listing before it reaches a command line, under a repo-relative grammar with no `..` segment, no leading `-`, and no shell metacharacter. The screen closes two holes at once: the injection reach, since an unvalidated value in a composed command is where injection lives whoever owns the template, and the softer exit where a report names a file the changeset never touched, reads clean, and so retires its own run-stopping tag. The doctrine already says a finding is a hypothesis until confirmed; this instances it at the one tag that halts a run. Cost: one git read per `mistake`, on the orchestrator's clock. Reversal: if a later incident shows the orchestrator skipping the read, the tool-grant option is the fallback, and it is recorded here so it is not re-derived.
- **The `mistake` tag keeps its power; the charter keeps its "make the call" line.** The curator still classifies without hedging. What changes is that the tag carries what it rests on, so the adjudicating step can tell a claim the curator read both sides of from a claim about a state it could not open.
- **One artifact, two readings, and the two kaizen notes about it become one section.** Note 2 (name the resolved-model artifact) and note 3 (a dispatch that never runs looks like a slow one) are answered by the same file: the assistant lines of `agent-<id>.jsonl` carry the resolved model and are also the proof a turn was taken. They edit the same paragraphs of finishing-work, and the project memory records that skill amendments collide with unchanged neighbours, so they ship as one section with reviewers briefed to read the whole rule.
- **The never-started windows are set from data, not the asymmetry.** Measured over every subagent transcript on SCOTT-CLAUDE (1,999 files under `~/.claude/projects`, 1,988 with a first assistant turn): first-turn latency p50 2.1 s, p90 4.3 s, p95 6.3 s, p99 12 s, one outlier at 574 s (opus, 2026-08-17), the next at 112 s. Eleven transcripts never took an assistant turn, every one of them carrying `"model":"fable"` in its `.meta.json`, dated 2026-08-19 to 2026-08-23, including the two ai-os finishing reviewers behind the SCOTT-CLAUDE note and the three claude-kit finishing reviewers of 2026-08-23 00:40. A five-minute first-turn window is twenty-five times p99; the one outlier in 1,988 would have been re-dispatched at no loss, since it had built nothing. The five-minute probe window that follows is the discriminator the existing rule already uses (an agent that can take a round answers at its next tool round), sized to the same reasoning.
- **Byte growth stays the stall reading for a started agent.** The existing hallmark is right about a dispatch that wrote and then went quiet; the growth window and its probe are untouched for that shape. What this plan corrects is the reading for a dispatch that never wrote an assistant line: the current text says finding no file is a real zero and a dispatch that has taken no step has written nothing to create, and both halves are false on this harness (the file exists from dispatch, with the prompt), so a session measuring bytes reads a 17 KB file that never grows and cannot tell it from a stalled run without the full window.
- **A `<synthetic>` model line is not a turn.** Eight transcripts on this box carry an assistant line whose `message.model` is `<synthetic>`; each is the harness's own API-error placeholder ("API Error: Connection lost mid-response"). The turn count excludes them.
- **The harness fact goes to the operator tier.** That an accepted model override the account cannot serve creates a dispatch that never errors and never runs is true of this harness on this operator's machines, not of one project, so it is written with `memq add-operator` per the memory-system skill, with the figures above.
- **The after-query lives in the close-out, once.** The doctrine's same-turn rule fixes a recalled memory that evidence contradicts; it cannot reach a record the effort's recall never surfaced, because that recall ran with the vocabulary the session had before the change, and a stale record hides behind the words you did not yet know to search. The close-out is where the new vocabulary exists and where supersedes are written, so the after-query goes in finishing-work step 7 beside the ledger settlement. It does not go in executing-work's per-Chapter sweep, which stamps applied memories and does not search; a per-section search would cost a query per section to catch what the close-out catches once.
- **The guard exempts a heredoc body only where the shell would never run it.** The guard's own header names the false hit as accepted (a governed verb in a body "still denies") because a body reaching a shell is a command wherever it sits. The exemption is therefore positive rather than default: a quoted delimiter (literal body), an owning command that is a data sink (`cat` or `tee`, with any redirects), no member of the guard's executor list in command position anywhere on the introducing logical line (which covers `| sh`, `bash <<`, and `eval "$(cat <<`), and no unquoted `#` at word start before the operator on that line (a comment-position introduction opens no heredoc, so its "body" is live commands, which test `an introduction in comment position cannot hide a verb` pins). Two further conditions come out of building the exemption against a control battery rather than out of the design, and both only ever remove exemption, so each restores a pre-change deny. The text under analysis is the top-level command rather than a payload some executor was handed: `sh -c "cat <<'EOF' ... EOF" | sh` runs the body, while the payload read on its own is a sink copying stdin, because what consumes the executor's own stdout sits in the command around it and outside the string under analysis. And no process substitution stands before the operator on the introducing line, since `. <(cat <<'EOF'` hands the body to a reader that may be `source`; that joins the command-substitution spellings already listed. One property has to hold for any of that to be sound, and stating it as a condition rather than assuming it is what the first implementation got wrong: **the window the exemption reasons over must be at least as wide as the window the shell parses**. A condition scoped to the introducing logical line bounds nothing, because the shell reads the whole command, so a consumer moved outside that line (`( cat <<'EOF' ... ) | sh`), a substitution opened on an earlier line (`eval $(` then the introduction beneath it), and a second introduction sitting inside an already-exempted body (whose mask then runs past the outer terminator and hides every line after it) each escape a one-line check while executing normally. The last of those is the worst shape in the class: it hides an arbitrary command behind a fixed two-line prefix, and a hidden `git push` or `gh pr merge` leaves the worktree byte-identical, so the tree-state check cannot see it either.

So the exemption recognizes one shape rather than detecting escapes from many, which is the structural correction two review rounds converged on. A condition set that asks whether any known escape is present is a denylist over shell grammar, and shell grammar is not enumerable: each round closed the spellings it was shown and left a fresh class, and the conditions were themselves read off a quote-masked copy of the command that a single unbalanced quote inside the body blanks, so they could pass vacuously on text the body's author wrote. The exemption therefore applies only where the whole command string matches one tight shape, and every other command is scanned exactly as today. The shape is a single simple command: one `cat` or `tee` owning one heredoc whose delimiter is quoted, one `>` or `>>` redirect carrying no file-descriptor prefix or one `tee` file operand, that target resolving inside the class's writable set, the heredoc terminator matched by bash's own rule (`^DELIM$` for `<<` and `^\t*DELIM$` for `<<-`, no other leading whitespace tolerated), and nothing else anywhere in the string: no second `<<` operator, no separator (`;`, `&`, `&&`, `||`, or a newline outside the body), no pipe, no redirect beyond the one, no subshell or brace group, no command or process substitution, no backslash continuation, no `#`, and no unbalanced quote. Anything outside that shape leaves the body scanned. The property the previous design asserted in prose then holds structurally rather than by argument: the window cannot be narrower than the shell's, because the shape admits no construct that would make the two windows differ. Every bypass either round verified requires one of the excluded constructs, so each dies by construction rather than by a condition aimed at it. The cost is that a report heredoc preceded by a gather step in the same command is no longer exempt, which the same round found was already a false deny, so nothing that worked is lost. The residual narrows with it and is stated rather than closed: a literal body written to a class-writable path and run by a later, separately scanned command is unseen here exactly as `printf '<mutation>' > .kit/x.sh` already is, backstopped by the tree-state check for a file delta and not for a git mutation. It is stated by shape rather than by one example, naming the spellings that actually reach it (`. <path>`, `source <path>`, an interpreter with a file operand, `$(cat <path>)`) rather than the one the executor screen happens to catch.

Separately, and not caused by this plan, the guard masks the interior of a double-quoted span whole, so a command substitution the shell does perform inside double quotes is never scanned: `echo "$(git commit -m x)"` allows while the unquoted spelling denies, for every governed verb and both agent classes. That is a complete one-line bypass of an access-control hook, in a file this plan already opens, so it is closed here rather than parked, and the guard's own header claim that quoting is not a way around it becomes true rather than aspirational.

## Standing Brief Amendments

Added 2026-08-26, on the resumed run, and recorded as approval drift. Each entry is a finding class this plan's own review rounds surfaced at more than one site, so step 4's recurrence rule makes it standing content every later section inherits, dispatched or inline. The block was owed from the second recurrence and is written once here rather than restated per brief.

1. **An amendment owns every sentence that reasons about what it changed, and a diff cannot show that class.** This effort's dominant defect is a correction that is right in itself and leaves an unchanged neighbour asserting the superseded rule; eight review rounds on one rule found it every time, and five independent lenses found one instance of it. So read the whole rule rather than the diff, and sweep the neighbours in the same edit: a sentence prescribing a window, naming a condition, or drawing a conclusion the amendment retires is falsified by it whether or not the amendment touched the line.
2. **A rule that names a reading names its spelling, and the spelling is run against real data with a control before it ships.** Three spellings on this plan did something other than what the sentence above them claimed: a substring tally counting occurrences rather than turns, a real newline written where a literal escape was needed, and a count that flipped to binary mode on a NUL byte and emitted a notice that passed the filter. Reading a spelling cannot catch any of these; running it against a transcript that holds the thing, plus a control that holds none of it, catches all three.
3. **An access-control instrument fails silently toward permissive, so score its statuses rather than its silence.** A probe treating any non-deny exit as an allow read a syntax error as a clean bypass, and a hand-built payload carrying an invalid escape made the hook fail open, which reads exactly like an allow. Treat any status outside the expected pair as void rather than as a result, and build a hook payload with a real serializer rather than by hand.
4. **A deny case earns its green only by discriminating the condition in its own title, proven by granting the condition rather than by deleting its line.** This suite has been green over live bypasses at 88/88, at 94/94 and at 96/96, every time because each case failed an earlier structural check and never reached the condition it was named for. A deleted line falls through to a downstream check and reads as subsumed when it is only backstopped.
5. **A control that reads zero certifies nothing.** Two absence checks on this plan returned a clean zero for the wrong reason: a grep run against a safety copy taken before the text existed, and a counting pipeline printing a bare zero on a wrong path while sending its complaint to stderr. Before a zero counts, show the same instrument speaking against a state known to hold the thing.
6. **Where the parser cannot confidently resolve what the shell will run, it denies.** The operator's 2026-08-24 ruling on Section 4 settles the guard's posture: fail closed on exactly the ambiguity a bypass exploits, since an allow-list's maintenance lapse fails open while an ambiguity check's failure fails closed and announces itself. Text the guard declines to scan is unresolved rather than absent, and dropping it silently is the shape of every Critical this section produced.
