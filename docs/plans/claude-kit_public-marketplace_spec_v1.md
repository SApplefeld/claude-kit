# A public marketplace repository carries the four plugins and nothing else, filled by a tag-triggered publish job from each private repository, so the source repositories can go private

Status: Ready
Commit Model: Branch-and-PR
Created: 2026-10-02

The ARCHITECT persona wrote this plan on 2026-10-02 on the operator's decisions of 2026-09-28, recorded in `docs/backlog.md` under "Plugins-only public distribution across all three repos", and his rulings of 2026-10-02 on the ARCHITECT's channel: the public repository is `SApplefeld/plugins`, the fleet's hosts uninstall every plugin and reinstall only from the public marketplace, the private clones stay for development, releases are cut by tag, and llm-wiki goes private with a cleaned public copy as the fourth entry, `wiki`, under its own plan. It is the fourth of the rename's four plans and the carrier of the shared design: the persona repository's `agent_persona_public-marketplace_spec_v1.md`, the relay repository's `channels_public-marketplace_spec_v1.md` and the wiki repository's `llm-wiki_public-engine_spec_v1.md` are its three siblings, each adding the same job to its own repository. It has one precondition, on dispatch: `claude-kit_grimoire-rename_spec_v1.md` has merged, so the plugin folder is `plugins/grimoire/`. The coordinator queues it for the kit's worker then. While the four source repositories are public, no commit, pull request, Chapter or brief on this plan spells any word on the banned list or the path of a file that leaks one, per the operator's correction of 2026-09-28.

## Goal

A public GitHub repository `SApplefeld/plugins` holds `.claude-plugin/marketplace.json` naming the marketplace `applefeld` with four entries, `grimoire`, `personas`, `relay` and `wiki`, a short README for an installer, and one folder per plugin that holds only that plugin's runtime files. Each job replaces its own folder and nothing else, so the root stays what the operator created and the kit's job seeded. Each private repository carries a GitHub Actions workflow that runs on a pushed tag matching `publish-*` and on a manual run, assembles a snapshot from a committed allowlist of paths, fails on any path from a plan, backlog, kaizen or scratch zone and on any word from a list held only as a repository secret, and pushes one commit that replaces the public repository's folder for that plugin over an SSH deploy key, serialized per repository. The kit's job also seeds the marketplace file and the README when the public repository lacks them. A clean machine adds the public marketplace and installs all four plugins, and the operator then takes the four source repositories private.

## Approach

**The public repository's shape.** `SApplefeld/plugins`, created by the operator, default branch `main`. At its root: `.claude-plugin/marketplace.json`, `README.md`, and `plugins/grimoire/`, `plugins/personas/`, `plugins/relay/`, `plugins/wiki/`. The marketplace file names the marketplace `applefeld`, the owner as in this repository's marketplace file, and four entries: `grimoire` with source `./plugins/grimoire`, `personas` with source `./plugins/personas`, `relay` with source `./plugins/relay/plugins/relay`, and `wiki` with source `./plugins/wiki`. The wiki entry is a plugin by manifest alone: its folder holds the knowledge-base engine, and installing it places the engine where its setup script runs from. The relay's installed plugin is a shim that runs the broker from a live checkout, so its folder is a root-layout snapshot of its repository holding the broker, the wrapper and the install scripts, and the entry points at the manifest two levels in, at `plugins/relay/plugins/relay/.claude-plugin/plugin.json` in the public repository. No entry carries a `version`, so installs follow commits. The marketplace name is the one this host's kit install already uses, so `grimoire@applefeld` and the kit lookup in the persona plugin do not change; the fleet's private `applefeld` marketplace is removed from each host before the public one is added, since one machine cannot register two marketplaces under one name.

**The seed files, in this repository.** `tools/publish/public/` is the public repository's root as seeded: `.claude-plugin/marketplace.json`, the catalog above, and `README.md`, the installer's page. The page carries the four install commands; that the kit's session hook offers to wire its doctrine import; that the kit's doctor runs from the installed payload at `<plugin cache>/applefeld/grimoire/<sha>/doctor/doctor.cmd`, since the launcher at this repository's root does not ship; that the persona plugin's supervisor runs from the installed folder; that the relay needs a host install from its folder's install scripts; and that the wiki's setup script runs from its installed folder per the walkthrough shipped beside it. The kit's job copies the seed tree onto the public root, each file only where absent, so a later hand edit there survives. `claude plugin validate tools/publish/public` reads the seed as a marketplace directory.

**The allowlist, `tools/publish/allowlist.txt`.** One path or glob per line, relative to the repository root, resolved by `git ls-files` so an untracked file never ships. This repository's list is `plugins/grimoire/**`. Anything a glob resolves that matches the forbidden set fails the assembly. The set is root-relative: a path whose first segment is `docs`, `kaizen`, `.kit`, `test` or `tools`, or whose file name carries `.test.`. A segment deeper in the path is not the set, so `plugins/grimoire/skills/kaizen/SKILL.md` ships. A line that is a literal path rather than a glob is admitted past the set's first-segment rule, which is how a sibling ships one document under `docs/` by name; a literal path is still refused when its first segment is `docs/plans`, `docs/archive`, `kaizen` or `.kit`, or when its file name carries `.test.`, so no form of line ships a plan, an archive, a kaizen note or scratch. The forbidden set is a second guard over the allowlist and the reason a glob mistake cannot ship a plan.

**The assembler, `tools/publish/assemble.mjs`.** Node, builtins only. Arguments: `--allowlist <file>`, `--out <dir>`, and `--strip-version` for the relay. It resolves the allowlist through `git ls-files`, applies the forbidden set to glob results, copies each file under `--out` preserving its path, strips `"version"` from `.claude-plugin/plugin.json` under the flag, and prints the count copied. An empty resolution is a failure, since a job that published nothing would read as a success.

**The gate, `tools/publish/leak-gate.mjs`.** Node, builtins only. Arguments: `--root <dir>` and `--words-file <file>`. It reads the list, one word per line, trims and drops blanks, and scans every file under the root and every relative path under the root as a string; a word matches as a case-insensitive substring of a line or of a path. A file whose first 8 KiB holds a NUL byte is skipped as binary and counted in the summary line. On a content hit it prints the file's path and line number and nothing else, since the word must never reach a log. On a path hit it prints only `path hit` and the count of such hits, since the path is then the leak, and a file whose path hit prints no content hit, so its path never reaches the log by the other route. It exits 1 after the whole scan. An empty list is a failure, since an empty secret would pass everything. GitHub masks a secret's value in a run log, and the gate prints no matched text regardless, so the two guards stack; a run log is readable by anyone with read on the repository, and read widens whenever the repository is shared.

**The workflow, `.github/workflows/publish.yml`.** Triggers: `push` on tags `publish-*`, and `workflow_dispatch`. One job on `ubuntu-latest`, `concurrency` group `publish` so two tags serialize, Node 24. Every third-party action it uses is pinned to a commit SHA. Steps: check out the tag; run the assembler into a temporary directory; write the secret `PUBLISH_BANNED_WORDS` to a temporary file outside both the snapshot root and the clone, and run the gate on the snapshot; set up SSH with the secret `PUBLISH_DEPLOY_KEY` and GitHub's SSH host keys pinned in the workflow from GitHub's published list, never from a run-time scan; clone `git@github.com:SApplefeld/plugins.git` at depth 1; seed the catalog and README where absent; remove `plugins/grimoire` in the clone and copy the snapshot's `plugins/grimoire/` onto it, so the manifest lands at `plugins/grimoire/.claude-plugin/plugin.json` where the catalog's source finds it, while a sibling whose allowlist is a root layout copies its snapshot whole onto its folder; commit as `Publish grimoire from claude-kit at <tag> (<short sha>).` with the committer `github-actions[bot] <41898282+github-actions[bot]@users.noreply.github.com>`, or exit 0 with a notice when the tree is unchanged; push, and on a rejected push pull with rebase once and push again, since the four jobs write disjoint folders. The secret names are the 2026-09-28 record's. The workflow file has no offline parser in this repository, so its first run under `## Operator Verification` is its check, and the section reads it by hand against GitHub's workflow syntax.

**The siblings.** The persona, relay and wiki repositories each carry the same two scripts byte for byte under `tools/publish/`, their own allowlist, their own workflow with their plugin's name and folder, and no seed files. The persona repository's list is its runtime: `.claude-plugin/plugin.json`, `hooks/**`, `bin/**`, `skills/**`, `package.json`, `package-lock.json` and `tsconfig.json`. That answers the backlog's prerequisite (2), which said the persona repository's root is its plugin so `docs/` and `.kit/` would ship, and asked for either a subfolder or an allowlist of runtime paths. The relay's list is its root layout minus documents and tests, with `--strip-version`. The wiki's list is its engine with a manifest added for the entry. Each sibling plan names its own list.

**The tests.** `test/publish-assemble.test.js` builds a fixture repository under a temporary directory with `git init` and runs the assembler on it: a list naming two files copies those two and no third; a glob resolving a path whose first segment is `docs` fails naming it; a glob resolving `plugins/x/skills/kaizen/SKILL.md` ships it; a literal line `docs/install.md` ships that file while literal lines `docs/plans/x.md`, `kaizen/notes-x.md` and `docs/a.test.md` are refused; a list resolving nothing fails; the flag strips `version` and leaves every other key. `test/publish-leak-gate.test.js` builds a fixture tree the same way: a planted word from a temporary list fails with the file and line on stdout and the word absent from stdout and stderr; a word planted in a file name fails with `path hit` and no path on either stream, and the same file with the word in its content too prints no content hit; a file with a NUL byte is skipped and counted; a clean tree passes; an empty list fails. Both run under `node --test test/*.test.js`, with every fixture under a temporary directory and no committed fixture.

**The README and the security model.** `README.md` gains a section saying how a release is cut: tag trunk `publish-<YYYYMMDD>` or any `publish-` tag, push the tag, read the run, and what the job refuses. It names the two secrets by name and says the list's content lives nowhere in any repository. Its install step at `:176` names the public marketplace, `claude plugin marketplace add SApplefeld/plugins` then `/plugin install grimoire@applefeld`, and the clone's `--dev` load as the development path. `docs/security-model.md`'s section "What the public repository discloses" at `:894` opens on this repository being the public distribution surface, and `:696` and `:728` say "a clone of this public repository"; after this plan the source is private and the snapshot is the public surface, so the section is rewritten to say what the snapshot discloses, the allowlist and the gate being its bounds, and the two lines name the private repository.

**The scrub, prerequisite (1).** The backlog's first prerequisite says one style reference in this repository names a client, which must be scrubbed before the first publish. The worker asks the operator for the word on its thread, runs the gate locally with a temporary list holding it over the assembled snapshot, and rewrites the hit to a generic word before the section closes. The Chapter records the file by path and the line, never the word.
